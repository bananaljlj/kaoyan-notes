# 考研 408 计算机网络常见协议速查表

> 本表按 **TCP/IP 四层模型**为主，并在“所属层次”中给出常见的 OSI 对应层。协议的分层在不同教材中可能略有差异：例如 ARP 位于网络层与数据链路层的交界，TLS 横跨表示层/会话层，Ethernet 和 802.11 同时涉及数据链路层与物理层。表中“应用层”还包括一些为网络层提供控制信息的协议（如 RIP、OSPF、BGP），考试时要区分“协议报文封装在哪一层”和“协议实现的网络功能”。

## 一、分层总览

| TCP/IP 层 | OSI 对应 | 主要职责 | 典型协议/标准 |
|---|---|---|---|
| 应用层 | 应用层、表示层、会话层 | 为用户应用提供网络服务，定义报文格式和交互过程 | HTTP/HTTPS、DNS、DHCP、FTP、SMTP、POP3、IMAP、Telnet、SSH、SNMP、NTP、RIP、OSPF、BGP |
| 传输层 | 传输层 | 端到端进程通信、复用分用、可靠传输、流量控制和拥塞控制 | TCP、UDP、SCTP、QUIC（QUIC 常被视为基于 UDP 的新型传输协议） |
| 网际层 | 网络层 | 主机到主机的数据报传送、逻辑寻址和路由 | IPv4、IPv6、ICMP、ICMPv6、IGMP、IPsec、NAT |
| 网络接口层 | 数据链路层、物理层 | 相邻节点传输、成帧、MAC 寻址、差错检测、介质访问和比特传输 | Ethernet/IEEE 802.3、Wi-Fi/IEEE 802.11、PPP、HDLC、VLAN、STP、ARP |

## 二、物理层与数据链路层

| 协议/标准 | 所属层次（TCP/IP；OSI） | 功能 | 主要特点与 408 考点 |
|---|---|---|---|
| Ethernet / IEEE 802.3 | 网络接口层；数据链路层（MAC 子层）+物理层 | 规定有线局域网的帧格式、MAC 地址、介质访问和物理信号 | 以太网帧含目的/源 MAC、类型/长度、数据、FCS；现代交换式全双工以太网通常不再使用 CSMA/CD 竞争。 |
| CSMA/CD | 网络接口层；数据链路层（MAC） | 共享式半双工以太网的介质访问控制 | 载波监听、多址接入、碰撞检测；发生碰撞后采用二进制指数退避。只适用于共享介质，不能用于无线局域网。 |
| Wi-Fi / IEEE 802.11 | 网络接口层；数据链路层 +物理层 | 无线局域网接入、帧传输和认证 | 使用 CSMA/CA，通常通过 ACK、随机退避和 RTS/CTS 减少碰撞；无线站点难以边发送边检测碰撞。 |
| CSMA/CA | 网络接口层；数据链路层（MAC） | 无线介质访问控制 | 载波监听、多址接入、碰撞避免；发送前等待随机退避，必要时使用 RTS/CTS。 |
| PPP | 网络接口层；数据链路层 | 点到点链路上的封装、链路建立和认证 | 面向点到点链路；包括 LCP（链路控制）和 NCP（网络层协议控制）；可进行 PAP/CHAP 认证，有 FCS 差错检测，但不负责纠错。 |
| HDLC | 网络接口层；数据链路层 | 同步、面向比特的数据链路控制 | 用标志字段和零比特插入实现帧定界；支持确认、流量控制和差错控制。 |
| VLAN / IEEE 802.1Q | 网络接口层；数据链路层 | 在一个物理交换网络中划分逻辑广播域 | 在以太网帧中加入 VLAN 标签；不同 VLAN 默认不能直接形成同一广播域，跨 VLAN 通信需三层设备。 |
| STP / IEEE 802.1D | 网络接口层；数据链路层 | 消除交换机二层环路 | 通过选根桥、计算最短路径并阻塞冗余端口形成无环生成树；RSTP（802.1w）收敛更快。 |
| LACP / IEEE 802.1AX | 网络接口层；数据链路层 | 将多条物理链路聚合成一条逻辑链路 | 提高带宽和可靠性；链路聚合不等同于 IP 层路由。 |
| ARP | 网际层与网络接口层之间；常归入网络层（也常称网络接入层协议） | 根据 IPv4 地址查询同一局域网中的 MAC 地址 | 请求通常广播、应答通常单播；结果缓存在 ARP 表中；只解决同一广播域内的下一跳映射，不跨路由器。 |
| RARP | 网际层与网络接口层之间（历史协议） | 根据 MAC 地址查询 IP 地址 | 已基本被 BOOTP/DHCP 取代；了解其“反向 ARP”含义即可。 |
| PPPoE | 网络接口层；数据链路层 | 在以太网上承载 PPP，常用于宽带拨号 | 保留 PPP 的认证、协商能力；以太网承载 PPP 会产生额外封装开销。 |

## 三、网际层（网络层）

| 协议/机制 | 所属层次（TCP/IP；OSI） | 功能 | 主要特点与 408 考点 |
|---|---|---|---|
| IPv4 | 网际层；网络层 | 提供无连接、尽力而为的主机到主机数据报服务和逻辑地址 | 地址 32 位；首部含 TTL、协议号、首部校验和、分片字段；不保证可靠、按序或不重复交付。 |
| IPv6 | 网际层；网络层 | 扩展地址空间并改进分组处理 | 地址 128 位；基本首部固定 40 字节、无首部校验和；用扩展首部承载选项，路由器通常不分片，分片由源主机完成。 |
| ICMP | 网际层；网络层 | 报告 IP 传输中的差错和诊断信息 | 不向应用直接提供可靠传输；回显请求/应答用于 ping，超时报文与 traceroute 有关；ICMP 报文封装在 IP 数据报中。 |
| ICMPv6 | 网际层；网络层 | IPv6 的差错报告、诊断和邻居发现支持 | 邻居发现（NDP）替代 IPv4 中 ARP 的主要功能；还支持路径 MTU 发现等。 |
| IGMP | 网际层；网络层 | IPv4 主机与本地路由器之间管理组播成员关系 | 解决“主机是否加入某组播组”，不负责跨网络的组播路由；组播路由还需配合 PIM 等协议。 |
| IPsec | 网际层；网络层 | 为 IP 通信提供认证、完整性、机密性和抗重放保护 | AH 提供认证/完整性，ESP 还可提供加密；支持传输模式和隧道模式，常用于 VPN。 |
| NAT | 网际层；网络层功能（不是单一标准协议） | 转换私有地址与公网地址，缓解 IPv4 地址不足 | 常见 NAPT 还转换端口号；破坏端到端地址透明性，入站连接通常需端口映射或其他穿透机制。 |
| RIP | 应用层报文、服务于网络层；OSI 常记为应用层控制协议 | 在自治系统内部进行距离向量路由 | 以跳数为度量，最大有效跳数 15，16 表示不可达；周期性交换完整/部分路由表，收敛较慢，适合小型网络。 |
| OSPF | 应用层报文、服务于网络层；OSI 常记为应用层控制协议 | 在自治系统内部进行链路状态路由 | 使用 SPF（Dijkstra）算法；按区域组织，支持 VLSM/CIDR、认证和等价多路径；IP 协议号为 89，不使用 TCP/UDP 端口。 |
| BGP-4 | 应用层报文、服务于网络层；OSI 常记为应用层控制协议 | 在自治系统之间交换可达性信息并实施策略路由 | 路径向量协议；使用 TCP 179 端口；通过 AS-PATH 等属性防环并按策略选路，是互联网域间路由的核心。 |
| IS-IS | 应用层控制协议、服务于网络层 | 自治系统内部链路状态路由 | 基于链路状态和 SPF；可支持 IPv4/IPv6，运营商网络中较常见；408 通常掌握其与 RIP/OSPF 的分类即可。 |

## 四、传输层

| 协议 | 所属层次（TCP/IP；OSI） | 功能 | 主要特点与 408 考点 |
|---|---|---|---|
| TCP | 传输层；传输层 | 为应用提供面向连接、可靠的字节流服务 | 三次握手建立连接，四次挥手释放连接；序号、确认、重传、校验和保证可靠性；滑动窗口实现流量控制，慢启动/拥塞避免/快重传/快恢复实现拥塞控制；全双工、面向字节流，不保留应用报文边界。 |
| UDP | 传输层；传输层 | 提供无连接的用户数据报服务 | 首部仅 8 字节；无连接、无可靠性、无顺序保证和拥塞控制，开销小、时延低；保留应用报文边界，支持一对一、一对多和多对多。 |
| SCTP | 传输层；传输层 | 为信令等应用提供可靠消息传输 | 面向消息而非字节流，支持多流和多宿主；408 了解概念即可。 |
| QUIC | 传输层/应用层之间（基于 UDP）；常按新型传输协议理解 | 提供可靠、有序（可多流）的加密传输 | 在用户态实现，内置 TLS 1.3，支持快速握手和连接迁移；解决 TCP 队头阻塞的一部分问题；不属于传统 408 必考核心。 |

## 五、应用层及其控制协议

| 协议 | 所属层次（TCP/IP；OSI） | 功能 | 主要特点与 408 考点 |
|---|---|---|---|
| DNS | 应用层；应用层 | 将域名解析为 IP 地址，也可反向解析及保存其他资源记录 | 分布式层次化命名系统；根、顶级域、权威/递归服务器；通常 UDP 53，区域传送等场景使用 TCP 53；常见记录有 A、AAAA、CNAME、MX、NS。 |
| DHCP | 应用层；应用层 | 动态分配 IP 地址、子网掩码、默认网关、DNS 等配置 | 基于 UDP 67（服务器）/68（客户端）；初始过程常记为 DORA：Discover、Offer、Request、ACK；客户端尚无 IP 时使用广播。 |
| HTTP | 应用层；应用层 | Web 客户端与服务器传输资源 | 请求/响应模式；无状态；HTTP/1.1 常用持久连接，HTTP/2 支持多路复用，HTTP/3 基于 QUIC；默认 TCP 80（HTTP/3 通常使用 UDP）。 |
| HTTPS | 应用层 + TLS；应用层与表示/会话层功能 | 通过 TLS 加密和认证 HTTP 通信 | HTTPS = HTTP over TLS；提供机密性、完整性和服务器身份认证；通常 TCP 443，HTTP/3 场景通常为 UDP 443。 |
| TLS / SSL | 表示层/会话层功能（TCP/IP 通常归入应用层安全协议） | 协商密码套件、认证身份、建立会话密钥并保护上层数据 | SSL 是历史名称，TLS 是现行标准；TLS 本身不负责可靠传输，通常承载于 TCP，也可由 QUIC 使用其握手机制。 |
| FTP | 应用层；应用层 | 文件上传、下载、目录管理 | 控制连接 TCP 21，数据连接 TCP 20（主动模式）；有状态，支持认证和多种传输模式；明文传输，安全替代方案常为 FTPS/SFTP。 |
| TFTP | 应用层；应用层 | 简单文件传输，常用于启动或配置 | 基于 UDP 69；功能少、无认证，依赖简单的确认与重传；比 FTP 开销小。 |
| SMTP | 应用层；应用层 | 邮件提交和邮件服务器之间的转发 | “推”协议；TCP 25 用于服务器间转发，587 常用于邮件提交，465 常用于隐式 TLS；邮件内容格式通常配合 MIME。 |
| POP3 | 应用层；应用层 | 从邮件服务器取信 | “拉”协议；TCP 110（TLS 常用 995）；传统模式倾向于下载到本地并删除服务器副本，功能比 IMAP 简单。 |
| IMAP | 应用层；应用层 | 在服务器上管理和同步邮件 | TCP 143（TLS 常用 993）；支持文件夹、状态同步和多设备访问，邮件通常保留在服务器。 |
| MIME | 应用层/表示层功能 | 描述邮件正文类型并支持非 ASCII 文本、附件等 | 通过 Content-Type、Content-Transfer-Encoding 等字段扩展 SMTP 的内容能力；不是独立的传输协议。 |
| Telnet | 应用层；应用层 | 提供远程终端登录 | TCP 23；明文传输用户名、密码和数据，安全性差。 |
| SSH | 应用层；应用层（含会话/安全功能） | 提供安全远程登录、命令执行和端口转发 | TCP 22；通过加密、完整性校验和主机/用户认证保护会话，可替代 Telnet。 |
| SNMP | 应用层；应用层 | 网络设备监视、管理和故障报告 | 管理站—代理模式；MIB 定义管理对象；常用 UDP 161（查询/设置）和 UDP 162（Trap）；SNMPv3 增强认证与加密。 |
| NTP | 应用层；应用层 | 在网络中同步计算机时钟 | 通常使用 UDP 123；采用分层时钟源（stratum）；时间同步对日志、认证和分布式系统很重要。 |
| RTP / RTCP | 应用层；应用层 | RTP 传输实时音视频，RTCP 反馈质量与同步信息 | 常基于 UDP；RTP 提供序号和时间戳但不保证可靠，适合实时性优先场景；常与 SIP 等信令协议配合。 |
| SIP | 应用层；应用层 | 建立、修改和结束多媒体会话 | 常用 UDP/TCP 5060，TLS 5061；主要负责信令，不直接承载音视频媒体。 |
| MQTT | 应用层；应用层 | 物联网中的轻量级发布/订阅消息传输 | 基于 TCP，支持主题、代理、QoS 等；408 一般作为扩展知识了解。 |
| RPC | 应用层/会话层功能 | 让程序调用远程主机上的过程 | 屏蔽网络通信细节；通常需要序列化、寻址、超时和错误处理；不是某一个固定线缆或端口协议。 |

## 六、容易混淆的对照

| 对照 | 记忆要点 |
|---|---|
| TCP 与 UDP | TCP：连接、可靠、字节流、拥塞控制；UDP：无连接、尽力而为、报文、低开销。 |
| HTTP 与 HTTPS | HTTPS 不是新的应用语义协议，而是 HTTP 加 TLS 的安全组合；默认端口通常为 80/443。 |
| FTP 与 TFTP | FTP 功能完整且基于 TCP；TFTP 功能简单、基于 UDP、常用于启动/配置。 |
| SMTP、POP3、IMAP | SMTP 负责发送/转发；POP3、IMAP 负责收取；IMAP 更强调服务器端管理和多设备同步。 |
| ARP 与 DNS | ARP 是本地 IPv4 地址到 MAC 地址的解析；DNS 是域名到 IP 地址（及其他记录）的分布式解析。 |
| RIP、OSPF、BGP | RIP：距离向量、跳数、AS 内；OSPF：链路状态、SPF、AS 内；BGP：路径向量、策略、AS 间。 |
| CSMA/CD 与 CSMA/CA | CD 用于共享式有线以太网的碰撞检测；CA 用于无线网络的碰撞避免。 |
| 流量控制与拥塞控制 | 流量控制关注发送方不要压垮接收方（TCP 接收窗口）；拥塞控制关注不要压垮网络（TCP 拥塞窗口）。 |
| MAC 地址与 IP 地址 | MAC 是链路层局部寻址，通常 48 位；IP 是网络层逻辑寻址，用于跨网络路由。 |

## 七、考试答题时的快速判断

1. 看到“可靠、有序、连接、滑动窗口、拥塞控制”，优先想到 **TCP**；看到“简单、实时、广播/组播、低开销”，优先想到 **UDP**。
2. 看到“域名、邮件、网页、文件、远程登录、设备管理”，通常是 **应用层协议**；端口号往往是应用层协议的辅助记忆点。
3. 看到“IP 地址、路由、TTL、分片、差错报告”，通常是 **网络层**；看到“MAC、帧、交换机、广播域、碰撞”，通常是 **数据链路层**。
4. “协议属于哪一层”要按题目语境作答：RIP/OSPF/BGP 的报文常归应用层控制协议，但它们完成的是网络层路由功能；ARP 则处于网络层与数据链路层的交界。
