## 二、核心知识框架

### 1. 文件系统解决什么问题

文件系统把用户看到的“文件名、目录、读写操作”映射到磁盘上的数据块，并负责：

- **按名存取**：用户不必记住物理块号，只需使用路径名和文件名。
- **目录组织**：维护文件名到文件控制信息的映射。
- **文件属性管理**：保存文件类型、长度、权限、时间、数据块地址等。
- **外存空间管理**：记录哪些磁盘块空闲，完成分配、回收和连续空间查找。
- **保护与共享**：检查用户权限，支持硬链接、符号链接等共享方式。
- **统一接口**：通过系统调用和 VFS 屏蔽不同文件系统的实现差异。

从用户观点看，最直接的目的就是**按文件名存取文件**（第 72 题）。保护、组织和提高利用率是重要功能，但不是该题所问的最直接答案。

### 2. 逻辑文件系统的功能

逻辑文件系统位于文件系统的上层，面向文件名、目录和保护，不直接负责具体磁盘块的物理读写。第 73 题的四项均可归入文件系统的逻辑管理职责：

1. **文件按名字存取**：把路径名解析为目录项和文件控制信息。
2. **文件目录组织管理**：维护目录层次、目录项和路径检索。
3. **文件名转换为文件描述符或文件句柄**：`open()` 成功后返回描述符，后续用描述符访问。
4. **存储保护**：依据用户身份、组身份和权限位/ACL 检查操作是否合法。

要区分：

| 层次 | 主要工作 |
|---|---|
| 逻辑文件系统 | 文件名、目录、FCB/inode、保护、打开文件表 |
| 文件组织模块 | 将逻辑块号映射为物理块号，处理连续/链接/索引分配 |
| 基本文件系统和设备驱动 | 发出块 I/O 请求，完成具体设备访问 |

### 3. FCB、目录项、inode 与 VFS 对象

#### 3.1 文件控制块和目录项

文件控制块（FCB）是操作系统管理文件所需信息的集合，通常包含：文件类型、大小、所有者、权限、时间信息、数据块地址和链接计数等。

在 UNIX 风格文件系统中，文件名和其他属性分开保存：

| 结构 | 典型内容 |
|---|---|
| 目录项（directory entry/dentry） | 文件名、指向 inode 的编号或指针 |
| inode | 文件类型、权限、长度、时间、数据块地址、链接计数等 |
| 超级块（superblock） | 文件系统整体参数，如块大小、总块数、空闲块信息等 |
| file 对象 | 一次打开实例的状态，如访问方式和当前文件偏移 |

创建文件时，系统需要初始化 inode，并在目录文件中增加“文件名 + inode 号”的目录项；详细访问权限属于 inode 的属性，不应理解为写入目录项（第 70 题已在 4.2 复盘）。

#### 3.2 Linux VFS 的对象

Linux VFS 用统一抽象连接不同文件系统，常见对象包括：

- superblock object：描述一个已安装文件系统；
- inode object：描述一个文件或目录实体；
- dentry object：描述目录项以及路径解析关系；
- file object：描述一次打开文件实例。

“data 对象”不是 VFS 四类基本对象之一，因此第 83 题选 D。VFS 不是建立在虚拟内存中的文件系统，而是内核中的抽象层；它既可以承接本地文件系统，也可以承接网络文件系统（如 NFS）。

### 4. 文件系统容量、文件数和单文件大小

第 74 题中，正确说法是“一个文件系统可以存放的文件数量受限于文件控制块的数量”。原因是每个文件都需要一个 FCB/inode 或等价的控制结构；若 inode 数量固定，文件数就受到其限制。

其余说法为什么错：

- 文件系统容量可能只是磁盘上的一个分区，**不一定等于整块磁盘容量**。
- 单个文件大小还受索引结构、地址项位数、文件系统最大文件长度以及可用空间限制，不只是剩余空间。
- RAID、逻辑卷、网络文件系统等都可以让一个文件系统跨越多个物理设备。

### 5. 外存空闲空间管理的四种方法

| 方法 | 记录内容 | 找连续空间 | 额外空间规模 | 典型特点 |
|---|---|---|---|---|
| 空闲表法 | 空闲区的起始块号和长度 | 较容易 | 与空闲区段数有关 | 适合记录连续空闲区 |
| 空闲链表法 | 空闲块之间的指针 | 较困难 | 与空闲块数有关 | 实现简单，但查连续区慢 |
| 位示图法 | 每个块对应一个 bit | 扫描位图查找 | 与总块数有关 | 定位和计数方便 |
| 成组链接法 | 栈中一组空闲块号，组间链接 | 需进一步组织 | 分组保存，开销较小 | 适合大型文件系统 |

#### 空闲表法

每个表项记录一段连续空闲区的起始地址和长度，所以查找连续空间相对方便。它需要维护的是“空闲区段表”，不是逐块链。

#### 空闲链表法

每个空闲块中保存下一个空闲块的地址。链表只说明“哪些块空闲”，不天然记录一段连续区间，因此比较难一次找到足够长的连续空间（第 82 题）。

#### 位示图法

用一个 bit 表示一个块或簇的状态，例如 `0` 表示空闲、`1` 表示已分配（具体 0/1 含义以题目约定为准）。位图大小由**总块数/总簇数**决定，不由当前空闲块数量决定（第 88 题）。

#### 成组链接法

空闲块分成若干组，系统在内存中的栈保存当前一组空闲块号，其中一个表项指向下一组。当前组耗尽时，再从下一组取出一组空闲块号。题目说“需要使用空闲盘块号栈/表”时，通常指成组链接法（第 79 题）。

### 6. 位示图计算通法

#### 6.1 位图所需字节数

若共有 `N` 个分配单位（块或簇），每个单位占 1 bit，则：

```text
位图大小（bit） = N
位图大小（Byte） = ceil(N / 8)
```

若题目给的是容量 `C` 和分配单位大小 `S`：

```text
单位数 N = C / S
位图字节数 = ceil(C / S / 8)
```

#### 6.2 行号和位号

若每个字长为 `w` 位，块号从 0 开始，位示图行号和列号从 1 开始，则块号 `n` 对应：

```text
行号 = floor(n / w) + 1
列号 = (n mod w) + 1
```

如果题目明确说块号也从 1 开始，则应先把 `n` 换算成第 `n` 个 bit，再计算；做题时不要把“块号起点”和“位示图行列起点”混为一谈。

#### 6.3 位图块号和字节号

设位图从磁盘块 `B0` 开始，每个磁盘块大小为 `S` 字节，目标磁盘块号为 `n`，且块号、字节号从 0 开始：

```text
每个位图块表示的磁盘块数 K = S × 8
位图块号 = B0 + floor(n / K)
块内剩余 bit 位置 r = n mod K
字节序号 = floor(r / 8)
```

若还问 bit 位号，再计算 `r mod 8`。

### 7. 簇、块、扇区和实际空间

文件系统可以按簇分配空间，一个簇通常包含多个扇区或磁盘块。遇到“按簇分配”时必须向上取整：

```text
分配簇数 = ceil(文件长度 / 簇大小)
实际占用空间 = 分配簇数 × 簇大小
```

位示图所表示的单位也要看题干：按簇分配就“一位对应一个簇”，不能误按扇区或字节计数。

### 8. 硬盘主引导扇区

传统 BIOS/MBR 分区方式中，硬盘第一个扇区的 MBR 主要包含：

- 主引导程序（boot code）；
- 分区表（partition table）；
- 末尾的有效标志等。

所以第 80 题选“包含分区表和主引导程序”。不要把 MBR 与某个分区的引导扇区混为一谈；GPT 分区表也不是传统 MBR 的同一结构。

### 9. VFS 的作用

VFS（Virtual File System）是内核中的统一文件系统接口层：

```text
用户系统调用
    ↓
VFS 统一接口（open/read/write/stat 等）
    ↓
具体文件系统（ext4、FAT、NFS……）
    ↓
块设备或网络设备
```

VFS 的核心是**统一接口和对象抽象**，不是提高某个文件系统的物理访问速度，也不是“虚拟内存中的文件系统”。

## 三、按顺序逐题复盘

### 第 72 题：从用户观点看引入文件系统的目的【错题】

> **题目：** 从用户的观点看，操作系统中引入文件系统的目的是（ ）。
>
> A. 保护用户数据　　B. 实现对文件的按名存取　　C. 实现虚拟存储　　D. 保存用户和系统文档及数据

**原作答：D　正确答案：B**

用户使用文件系统首先是为了用文件名/路径访问数据，而不是直接面对磁盘块号。A 和 D 是文件系统可以提供的功能或结果；C 属于虚拟存储管理，不是文件系统的目的。

**记忆：** 用户视角抓住“按名存取”；实现视角再补充目录、保护、空间管理和共享。

### 第 73 题：逻辑文件系统的功能【错题】

> **题目：** 逻辑文件系统的功能有（ ）。
>
> I. 文件按名字存取　　II. 文件目录组织管理　　III. 把文件名转换为文件描述符或文件句柄　　IV. 存储保护
>
> A. I、II 和 III　　B. II、III 和 IV　　C. I、II 和 IV　　D. I、II、III 和 IV

**原作答：B　正确答案：D**

四项都属于逻辑文件系统需要完成的工作：路径解析和按名存取、目录组织、`open()` 后建立描述符/句柄、权限检查。题目中的“逻辑文件系统”不是只指目录管理，保护同样属于其职责。

### 第 74 题：文件系统的容量和文件数【正确但需巩固】

> **题目：** 下列关于文件系统的说法中，正确的是（ ）。
>
> A. 一个文件系统可以存放的文件数量受限于文件控制块的数量

**正确答案：A**

每个文件都需要一个 FCB/inode 等控制结构。若控制块数量预先固定，能够创建的文件数也受其限制。文件系统容量是分区或逻辑卷容量，不一定等于整块磁盘容量；单文件大小还受寻址结构和最大文件长度限制。

### 第 75 题：UNIX 的文件索引结构【错题】

> **题目：** UNIX 操作系统中文件的索引结构放在（ ）。
>
> A. 超级块　　B. 索引结点　　C. 目录项　　D. 空闲块

**原作答：A　正确答案：B**

UNIX 使用 inode 保存文件属性和数据块索引地址。超级块描述整个文件系统，目录项主要负责文件名到 inode 的定位，空闲块用于数据或空闲空间管理。

### 第 76 题：文件存储空间管理的实质【错题】

> **题目：** 文件的存储空间管理实质上是对（ ）的组织和管理。
>
> A. 文件目录　　B. 外存已占用区域　　C. 外存空闲区　　D. 文件控制块

**原作答：A　正确答案：C**

文件数据块分配前必须找到空闲块，删除或缩短文件时还要回收块。因此外存空间管理的核心是维护空闲区，而目录和 FCB 是文件组织/属性管理的对象。

### 第 77 题：外存文件区管理目标【错题】

> **题目：** 对外存文件区的管理应以（ ）为主要目标。
>
> A. 提高系统吞吐量　　B. 提高输入输出速度　　C. 降低存储费用　　D. 提高存储空间的利用率

**原作答：B　正确答案：D**

外存文件区管理首先要减少碎片、及时回收和合理分配，使有限磁盘空间尽可能存放更多有效数据。吞吐量和 I/O 速度会受到分配策略影响，但不是此处的主要目标。

### 第 78 题：位示图的用途【正确但需注意语境】

> **题目：** 位示图可用于（ ）。
>
> A. 文件目录的查找　　B. 磁盘空间的管理　　C. 主存空间的管理　　D. 文件的保密

**正确答案：B**

本章讨论文件存储空间管理，位示图用于表示磁盘块或簇的分配状态。更广义地说，位图也可用于管理内存页框；但在本题选项和章节语境下选 B。位示图不负责目录查找或文件加密。

### 第 79 题：需要空闲盘块号栈的方法【错题】

> **题目：** 下列文件存储空间管理方法中，（ ）需要使用空闲盘块号栈（题图字样近似“空闲盘块号表”）。
>
> A. 空闲表法　　B. 空闲链表法　　C. 位示图法　　D. 成组链接法

**原作答：A　正确答案：D**

成组链接法把一组空闲块号放在栈中，栈满/耗尽时通过组间链接装入下一组。空闲表法保存的是空闲区的起始块号和长度；空闲链表法依靠块内指针；位示图法依靠 bit。

### 第 80 题：硬盘主引导扇区【正确】

> **题目：** 硬盘的主引导扇区（ ）。
>
> A. 包含引导记录　　B. 包含分区表和主引导程序　　C. 只包含主引导程序　　D. 只包含分区表

**正确答案：B**

传统 MBR 同时保存主引导程序和分区表，并带有有效标志。看到“主引导扇区”要想到“引导代码 + 分区信息”，不能只选其中一部分。

### 第 81 题：位示图行列定位【正确】

> **题目：** 若用 8 个字长 32 位组成的位示图管理内存，位示图行号和列号从 1 开始，则块号为 100 的内存块对应的位置是（ ）。
>
> A. 字号 3、位号 5　　B. 字号 4、位号 4　　C. 字号 3、位号 4　　D. 字号 4、位号 5

**正确答案：D**

标准约定块号从 0 开始。每个字表示 32 个块：

```text
字号 = floor(100 / 32) + 1 = 4
位号 = (100 mod 32) + 1 = 5
```

所以是 D。若题目另行规定块号从 1 开始，结果才会变成第 4 字第 4 位。

### 第 82 题：较难得到连续空间的管理方式【正确】

> **题目：** 比较难得到连续空间的空间管理方式是（ ）。
>
> A. 空闲链表　　B. 空闲表　　C. 位示图　　D. 成组链接

**正确答案：A**

空闲链表只沿链记录空闲块，想找连续的多个块必须遍历并比较块号；空闲表直接记录空闲区段，位示图可以扫描连续的 0，成组链接也可结合块号组织。因此本题选空闲链表法。

### 第 83 题：VFS 没有定义的数据对象【正确】

> **题目：** 下列选项中，不是 Linux 实现虚拟文件系统 VFS 所定义的对象类型的是（ ）。
>
> A. 超级块（superblock）对象　　B. 目录项（dentry）对象　　C. 文件（file）对象　　D. 数据（data）对象

**正确答案：D**

Linux VFS 的基本对象是 superblock、inode、dentry 和 file。题目照片中的 B 项括号字样较模糊，按 VFS 标准对象应理解为 dentry/目录项；无论如何，D 的 data object 不是 VFS 四类基本对象。

### 第 84 题：10GB 分区位示图大小【错题】

> **题目：** 文件系统容量为 10GB，磁盘空间按簇分配，簇大小为 4KB。采用位示图管理空闲空间，用 1 bit 标识一个簇是否分配，则位示图所需字节数为（ ）。
>
> A. 80　　B. 320　　C. 80K　　D. 320K

**原作答：C　正确答案：D**

按 1GB = 2^30B、1KB = 2^10B：

```text
簇数 = 10GB / 4KB = 10 × 2^18
位图大小 = 10 × 2^18 bit / 8
         = 10 × 2^15 Byte
         = 320KB
```

关键是题目按“簇”分配，所以先除以 4KB；再把 bit 除以 8 转成字节。

### 第 85 题：定位位示图中的块和字节【正确】

> **题目：** 文件系统用位示图表示磁盘分配情况，位图存于磁盘的 32～127 号块中；每块 1024B，块号和块内字节号均从 0 开始。若要释放的磁盘块号为 409612，则位图中要修改的位置所在的块号和块内字节序号分别是（ ）。
>
> A. 81,1　　B. 81,2　　C. 82,1　　D. 82,2

**正确答案：C**

每个位图块有 `1024 × 8 = 8192` 个 bit：

```text
位图块偏移 = floor(409612 / 8192) = 50
位图磁盘块号 = 32 + 50 = 82
块内剩余 bit = 409612 mod 8192 = 12
字节序号 = floor(12 / 8) = 1
```

因此答案为 `82, 1`。题目只问字节序号，不需要继续求第几个 bit。

### 第 86 题：管理空闲磁盘块的数据结构【错题】

> **题目：** 下列选项中，可用于文件系统管理空闲磁盘块的数据结构是：
>
> I. 位图　　II. 索引节点　　III. 空闲磁盘块链　　IV. 文件分配表（FAT）
>
> A. 仅 I、II　　B. 仅 I、III、IV　　C. 仅 I、III　　D. 仅 II、III、IV

**原作答：C　正确答案：B**

位图直接表示块状态；空闲磁盘块链直接链接空闲块；FAT 虽然主要记录文件簇链，但也能通过表项的空闲标记管理空闲簇。索引节点描述文件本身，不是空闲块管理结构，因此选 I、III、IV。

### 第 87 题：页框位示图大小【错题】

> **题目：** 某系统采用页式存储管理，用位图管理空闲页框。页大小为 4KB，物理内存大小为 16GB，则位图所占空间大小是（ ）。
>
> A. 128B　　B. 128KB　　C. 512KB　　D. 4MB

**原作答：A　正确答案：C**

物理页框数为：

```text
页框数 = 16GB / 4KB = 2^34 / 2^12 = 2^22
位图大小 = 2^22 bit = 2^19 Byte = 512KB
```

不要把 16GB 直接除以 8；位图的一个 bit 对应一个页框，必须先除以页大小。

### 第 88 题：外存管理结构开销与空闲块数量无关【正确】

> **题目：** 文件系统需要占用部分外存空间记录空闲块位置。在下列方法中，占用外存空间的大小与当前空闲块数量无关的是（ ）。
>
> A. 位图法　　B. 空闲表法　　C. 成组链接法　　D. 空闲链表法

**正确答案：A**

位图为每一个总块数预留 1 bit，因此大小由分区总块数决定。空闲表、空闲链表和成组链接都需要随着空闲块/空闲区数量变化而维护记录。

### 第 89 题：VFS 的统一接口【正确】

> **题目：** 下列关于虚拟文件系统（VFS）的叙述中，正确的是（ ）。
>
> A. VFS 是在虚拟内存中建立的文件系统
>
> B. VFS 能提高不同文件系统中文件的访问速度
>
> C. VFS 定义了可以访问不同文件系统的统一接口
>
> D. 通过 VFS 只能访问本地文件，不能访问网络文件

**正确答案：C**

VFS 提供统一的系统调用语义和对象接口，让上层程序不必关心底层是 ext4、FAT 还是 NFS。它主要解决兼容和抽象问题，不承诺提高物理访问速度，也不限制为本地文件。

## 四、易错点对照表

| 易混概念 | 正确区分 |
|---|---|
| 目录项 vs inode | 目录项主要保存文件名和 inode 定位信息；inode 保存属性和数据块地址 |
| inode vs 空闲块结构 | inode 管一个文件；位图/空闲链/FAT 管空间状态 |
| 空闲表 vs 空闲链表 | 空闲表记录连续区段；空闲链表逐块串联，找连续区困难 |
| 位示图 vs 成组链接 | 位示图一位对应一个块/簇；成组链接用栈保存一组空闲块号 |
| 文件系统容量 vs 磁盘容量 | 文件系统通常建立在分区/逻辑卷上，不必等于整盘容量 |
| 位图大小与什么有关 | 与总块数/总簇数有关，不与当前空闲块数有关 |
| VFS vs 虚拟内存 | VFS 是文件系统抽象层，不是内存中的“虚拟文件系统” |
| MBR vs 分区引导扇区 | MBR 含主引导程序和分区表；分区引导扇区属于某个分区 |
| 块号起点 vs 行列起点 | 题目可能分别规定；位示图行列从 1 开始不代表块号也从 1 开始 |

## 五、做题流程

1. **先找管理对象**：问的是文件/目录/inode，还是空闲磁盘块。
2. **再找管理单位**：按块、簇、扇区还是页框分配；位图的一位对应哪个单位。
3. **看到位示图先列公式**：总单位数 → bit 数 → 除 8 得字节；定位题再除以每个位图块覆盖的 bit 数。
4. **看到“连续空间”**：空闲表最直接；空闲链表最困难；位示图可扫描连续空闲位。
5. **看到“空闲盘块号栈”**：优先想到成组链接法。
6. **看到 VFS**：只抓“统一接口、统一对象、兼容不同具体文件系统”。
7. **看到 MBR**：记住“主引导程序 + 分区表”。
8. **计算后检查单位**：bit、Byte、KB、MB 不要混；容量题默认采用二进制换算，除非题目另有说明。

## 六、考前速记

```text
用户目的：按名存取
逻辑文件系统：按名存取 + 目录管理 + 名称转句柄 + 保护
UNIX 索引：inode
空间管理实质：外存空闲区
主要目标：提高空间利用率
连续空间难找：空闲链表
空闲盘块号栈：成组链接
位图开销：看总块数，不看当前空闲数
MBR：主引导程序 + 分区表
VFS：统一接口访问不同文件系统
位图：N 个单位需要 N bit = ceil(N/8) Byte
位示图定位（块号从 0）：行=floor(n/w)+1，列=n mod w+1
```

## 七、自测题

1. 一个 2GB 分区按 4KB 簇分配，用位图管理，位图需要多少字节？
2. 为什么空闲链表比空闲表更难找到连续空间？
3. 成组链接法中的栈耗尽时，系统如何获得下一组空闲块号？
4. 一个文件系统文件数为什么可能小于“剩余磁盘空间足够时理论上能存的文件数”？
5. VFS 为什么既不是虚拟内存，也不等同于某一种具体文件系统？

### 自测答案

1. 簇数 `= 2GB/4KB = 2^19`，位图大小 `= 2^19 bit / 8 = 2^16B = 64KB`。
2. 链表只保存逐块链接关系，必须遍历并比较块号才能确认连续性；空闲表直接保存空闲区起始位置和长度。
3. 从当前组的链接指针定位下一组，把下一组空闲块号读入栈，再继续分配。
4. 每个文件都需要 FCB/inode/目录项等控制结构；这些元数据数量或空间可能先耗尽。
5. VFS 是内核中的抽象接口层，统一上层系统调用和下层实现，可连接本地或网络文件系统。
