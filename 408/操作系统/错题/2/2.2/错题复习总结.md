## 二、核心知识框架

### 1. 调度的层次

| 调度层次 | 主要任务 | 状态变化 | 发生频率 |
|---|---|---|---|
| 高级调度（作业调度） | 从外存后备队列选择作业进入内存 | 后备态 → 创建/就绪态 | 最低 |
| 中级调度（内存调度） | 暂时换出进程或重新调入，以缓解内存压力 | 就绪/阻塞 ↔ 挂起 | 中等 |
| 低级调度（进程调度） | 从就绪队列选择进程获得 CPU | 就绪态 → 运行态 | 最高 |

中级调度的主要目标是调节内存中的进程数量、提高内存利用率，而不是直接提高 CPU 的运行速度。

### 2. 调度算法的评价指标

| 指标 | 希望方向 | 含义 |
|---|---:|---|
| CPU 利用率 | 越高越好 | CPU 忙于有效工作的时间比例 |
| 系统吞吐量 | 越高越好 | 单位时间完成的作业数量 |
| 周转时间 | 越短越好 | 完成时刻减到达时刻 |
| 带权周转时间 | 越小越好 | 周转时间除以实际运行时间 |
| 等待时间 | 越短越好 | 在就绪队列中等待 CPU 的总时间 |
| 响应时间 | 越短越好 | 从提交请求到首次得到响应的时间 |
| 公平性 | 需要保证 | 避免部分进程长期得不到服务 |

互斥性是并发控制要解决的问题，不是调度算法的评价指标。

常用公式：

```text
周转时间 = 完成时刻 - 到达时刻
          = 等待时间 + 运行时间 + I/O 等其他时间

带权周转时间 = 周转时间 / 实际运行时间

响应比 = (等待时间 + 要求服务时间) / 要求服务时间
       = 1 + 等待时间 / 要求服务时间
```

### 3. 什么时候会发生进程调度

可能引起调度的典型事件包括：

- 当前进程正常或异常终止；
- 当前进程主动阻塞；
- 时间片用完；
- 更高优先级进程进入就绪队列；
- 中断处理或系统调用结束、即将返回用户态时发现需要调度。

进程进入临界区并不意味着 CPU 不能切换。临界区的要求是：其他进程不能同时进入访问同一临界资源的临界区。正在临界区内执行的进程仍可能因时间片用完或中断而被抢占，只是对应资源仍保持被占用状态。

```text
临界区互斥 ≠ 关中断
不能同时访问临界资源 ≠ 不能切换 CPU
```

### 4. 进程上下文与上下文切换

进程上下文是进程恢复运行所需的全部环境，通常包括：

- CPU 现场：程序计数器、通用寄存器、栈指针等；
- 地址空间相关信息：页表基址寄存器等；
- PCB 中的状态、调度和资源管理信息；
- 用户栈、内核栈及程序的数据环境。

中断向量表是操作系统为整个系统建立的公共结构，并不属于某个进程的私有上下文。

上下文切换的主要过程：

```text
保存当前进程的 CPU 现场到 PCB
    ↓
由调度程序选择下一个进程
    ↓
装入下一个进程的地址空间和 CPU 现场
    ↓
从其上次停止处继续执行
```

切换时不会把进程的全部代码和数据从主存写入磁盘。是否发生换入换出属于存储管理决策，不是每次上下文切换的必做步骤。

### 5. 同一进程内的线程切换

同一进程的线程共享地址空间和打开文件等进程资源，因此线程切换只需更新线程私有的执行现场：

| 内容 | 同一进程内换线程是否更新 | 原因 |
|---|---:|---|
| 程序计数器 | 是 | 不同线程执行位置不同 |
| 栈基址/栈指针 | 是 | 每个线程拥有独立栈 |
| 页表基址寄存器 | 否 | 同一进程的线程共享地址空间 |
| 进程打开文件表 | 否 | 属于进程共享资源 |

而跨进程切换时，程序计数器、栈相关寄存器和页表基址寄存器都需要更新。

### 6. 常见调度算法对比

| 算法 | 是否抢占 | 优点 | 主要问题 | 适用倾向 |
|---|---:|---|---|---|
| FCFS | 否 | 简单、公平、开销小 | 护航效应，短作业和 I/O 繁忙型作业等待较久 | 批处理 |
| SJF | 通常否 | 同时到达时平均等待和周转时间较优 | 长作业可能饥饿，运行时间难准确预知 | 批处理 |
| SRTF | 是 | 新到短进程可抢占，平均周转时间较好 | 切换多，长作业可能饥饿 | 批处理 |
| 时间片轮转 | 是 | 公平、响应快 | 时间片过小开销大，过大退化为 FCFS | 分时系统 |
| 优先级调度 | 可抢占或非抢占 | 能体现任务重要程度 | 低优先级进程可能饥饿 | 实时/通用系统 |
| 高响应比优先 | 否 | 同时兼顾等待时间和运行时间 | 每次调度要计算响应比 | 批处理 |
| 多级反馈队列 | 是 | 响应快，兼顾多类进程 | 参数多、实现和调优复杂 | 通用/分时系统 |

时间片轮转中，时间片过大时，进程往往在时间片耗尽前就运行结束，算法会逐渐退化为 FCFS。

### 7. CPU 繁忙型与 I/O 繁忙型

- CPU 繁忙型进程具有较长的 CPU 区间，很少主动让出处理器。
- I/O 繁忙型进程经常运行很短时间就发起 I/O，然后进入阻塞态。

FCFS 容易出现护航效应：一个长 CPU 作业占用处理器时，大量完成 I/O 的短进程只能在后面等待，设备和 CPU 难以形成良好重叠。因此 FCFS 更有利于 CPU 繁忙型作业，而不利于 I/O 繁忙型作业。

动态优先级常采用下面的调整思路：

```text
时间片用完仍未完成 → 降低优先级，抑制 CPU 繁忙型进程
长期等待或刚完成 I/O → 适当提高优先级，照顾等待者和 I/O 繁忙型进程
```

### 8. 实时系统的调度

实时系统首先关注任务能否在截止时间前完成，因此通常采用基于优先级的抢占式调度。当更紧急或优先级更高的实时任务就绪时，它应能立即抢占当前任务。

时间片轮转强调公平和交互响应，但不能保证关键任务在截止时间前完成，因此不是实时系统的典型首选。

### 9. 优先级计算题的固定步骤

1. 确认“数值越大优先级越高”还是“数值越小优先级越高”。
2. 确认算法是抢占式还是非抢占式。
3. 按到达时刻标出所有新进程。
4. 每次到达、完成、阻塞或时间片结束时重新判断是否调度。
5. 画出 CPU 时间轴。
6. 根据时间轴计算完成时刻、周转时间或调度次数。

```text
非抢占式：当前进程一旦运行，通常执行到完成或阻塞
抢占式：更高优先级进程到达时，当前进程可能立即让出 CPU
```

调度次数统计的是“选择一个进程开始或恢复运行”的次数。进程被抢占后以后再次获得 CPU，需要再次计数；新进程到达但没有引起运行者变化，则不增加次数。

## 三、逐题复盘

### 第 03 题：调度算法的评价指标【错题】

> **题目：** 下列哪些指标是调度算法设计时应该考虑的？  
> I. 公平性  
> II. 资源利用率  
> III. 互斥性  
> IV. 平均周转时间  
> A. I、II  
> B. I、II、IV  
> C. I、III、IV  
> D. 全部都是

你的答案：**D**  
正确答案：**B，I、II、IV**

为什么错：公平性、资源利用率和平均周转时间都会衡量调度策略是否合理；互斥性解决的是多个进程如何安全访问临界资源，属于同步与互斥问题，并不是调度算法的评价指标。

### 第 06 题：临界区中的进程能否被调度【错题且存疑】

> **题目：** 在某单处理器系统中，若此刻有多个就绪态进程，则下列叙述中错误的是（　）。  
> A. 进程调度的目标是让进程轮流使用处理器  
> B. 当一个进程运行结束后，会调度下一个就绪进程运行  
> C. 上下文切换是进程调度的实现手段  
> D. 处于临界区的进程在退出临界区前，无法被调度

你的答案：**A**  
正确答案：**D**

为什么错：进入临界区只表示其他进程不能同时访问相同临界资源，不表示当前进程垄断 CPU。若时间片用完或发生更高优先级抢占，它仍可被切换出去；其他进程只是不能进入与该资源相关的临界区。

### 第 07 题：什么不属于进程上下文【错题】

> **题目：** 下列内容中，不属于进程上下文的是（　）。  
> A. 进程现场信息  
> B. 进程控制信息  
> C. 中断向量  
> D. 用户堆栈

你的答案：**D**  
正确答案：**C，中断向量**

为什么错：用户堆栈保存函数调用、局部变量等执行环境，属于进程上下文。中断向量表由操作系统统一维护，提供中断类型到处理程序入口的映射，不随进程切换而更换。

### 第 08 题：上下文切换不做什么【存疑但答对】

> **题目：** 下列关于进程上下文切换的叙述中，错误的是（　）。  
> A. 进程上下文指进程的代码、数据以及支持进程执行的所有运行环境  
> B. 进程上下文切换机制实现了不同进程在一个处理器中交替运行的功能  
> C. 进程上下文切换过程中必须保存换下进程在切换处的程序计数器值  
> D. 进程上下文切换过程中必须将换下进程的代码和数据从主存保存到磁盘

你的答案：**D**  
正确答案：**D**

你最终判断正确。每次上下文切换必须保存 CPU 现场，但进程代码和数据通常继续留在内存。只有存储管理决定换出进程时，相关页面才可能写入外存；上下文切换不等于进程换出。

### 第 09 题：同一进程内线程切换更新什么【错题】

> **题目：** 在支持页式存储管理和多线程技术的系统中，当一个进程中的线程 T1 切换到同一进程中的线程 T2 执行时，操作系统需要执行的操作是（　）。  
> I. 更新程序计数器的值  
> II. 更新栈基址寄存器的值  
> III. 更新页表基址寄存器的值  
> IV. 更新进程打开文件表  
> A. I、II、III、IV  
> B. II、IV  
> C. I、II  
> D. I、III、IV

你的答案：**D**  
正确答案：**C，仅 I、II**

为什么错：程序计数器和栈属于线程私有现场，需要切换；页表和打开文件表属于同一进程内线程共享的资源，不需要改变。判断这类题时先问：切换是否跨越了进程边界？本题没有。

### 第 10 题：FCFS 与护航效应【错题】

> **题目：**（　）有利于 CPU 繁忙型的作业，而不利于 I/O 繁忙型的作业。  
> A. 时间片轮转调度算法  
> B. 先来先服务调度算法  
> C. 短作业（进程）优先调度算法  
> D. 优先级调度算法

你的答案：**A**  
正确答案：**B，先来先服务**

为什么错：FCFS 中长 CPU 作业一旦排在前面，会长时间占用 CPU，使频繁进行短 CPU 运算和 I/O 的进程在后面等待，这就是护航效应。时间片轮转反而能让 I/O 繁忙型进程较快完成短 CPU 区间并发起 I/O。

### 第 12 题：实时系统采用什么调度算法【错题】

> **题目：** 实时系统的进程调度，通常采用（　）调度算法。  
> A. 先来先服务  
> B. 时间片轮转  
> C. 抢占式的优先级高者优先  
> D. 高响应比优先

你的答案：**B**  
正确答案：**C**

为什么错：实时系统首先要求重要任务在截止时间前得到处理。高优先级任务到达后必须能够及时抢占当前任务，因此通常采用抢占式优先级调度。时间片轮转保证公平，却不能提供确定的截止时间保障。

### 第 30 题：分时系统的典型调度算法【存疑但答对】

> **题目：** 分时操作系统通常采用（　）调度算法来为用户服务。  
> A. 时间片轮转  
> B. 先来先服务  
> C. 短作业优先  
> D. 优先级

你的答案：**A**  
正确答案：**A**

你最终判断正确。分时系统强调多个交互用户都能较快获得响应。时间片轮转让就绪进程依次获得一个时间片，能够兼顾公平性和响应速度。

### 第 38 题：何时降低进程优先级【错题】

> **题目：**【2010 统考真题】下列选项中，降低进程优先级的合理时机是（　）。  
> A. 进程时间片用完  
> B. 进程刚完成 I/O 操作，进入就绪队列  
> C. 进程长期处于就绪队列  
> D. 进程从就绪状态转为运行状态

你的答案：**D**  
正确答案：**A，进程时间片用完**

为什么错：时间片用完仍未结束，说明该进程可能偏 CPU 繁忙，降低其优先级能避免长期占用处理器。刚完成 I/O 的进程和长期等待的进程通常应受到照顾，可以保持或提高优先级。单纯从就绪态转为运行态不能说明应该降级。

### 第 47 题：非抢占优先级调度的平均周转时间【错题且存疑】

> **题目：**【2018 统考真题】某系统采用基于优先权的非抢占式进程调度策略，完成一次进程调度和进程切换的系统时间开销为 1 μs。在 T 时刻就绪队列中有 P1、P2 和 P3，其等待时间、需要的 CPU 时间和优先权如下表。若优先权值大的进程优先获得 CPU，从 T 时刻开始调度，则系统中三个进程的平均周转时间为（　）。

| 进程 | 已等待时间 | 需要的 CPU 时间 | 优先权 |
|---|---:|---:|---:|
| P1 | 30 μs | 12 μs | 10 |
| P2 | 15 μs | 24 μs | 10 |
| P3 | 18 μs | 36 μs | 20 |

> A. 54 μs  
> B. 73 μs  
> C. 74 μs  
> D. 75 μs

你的答案：**B**  
正确答案：**D，75 μs**

计算过程：P3 的优先权最高，先运行；P1、P2 优先权相同，已等待更久的 P1 先运行。因此顺序为：

```text
T        T+37       T+50        T+75
|--1--P3--|--1--P1--|--1---P2----|
```

每次调度和切换开销均为 1 μs：

| 进程 | 从 T 到完成的时间 | T 前已等待 | 周转时间 |
|---|---:|---:|---:|
| P3 | 1 + 36 = 37 | 18 | 55 |
| P1 | 37 + 1 + 12 = 50 | 30 | 80 |
| P2 | 50 + 1 + 24 = 75 | 15 | 90 |

```text
平均周转时间 = (55 + 80 + 90) / 3 = 75 μs
```

这道题的两个易漏点是：系统开销也占用时间；题目给出的“已等待时间”必须计入周转时间。

### 第 52 题：抢占优先级调度的调度次数【错题】

> **题目：**【2022 统考真题】进程 P0、P1、P2 和 P3 进入就绪队列的时刻、优先级（值越小优先权越高）及 CPU 执行时间如下表。若系统采用基于优先权的抢占式进程调度算法，从 0 ms 开始调度，到 4 个进程运行结束为止，发生进程调度的总次数为（　）。

| 进程 | 进入就绪队列时刻 | 优先级 | CPU 执行时间 |
|---|---:|---:|---:|
| P0 | 0 ms | 15 | 100 ms |
| P1 | 10 ms | 20 | 60 ms |
| P2 | 10 ms | 10 | 20 ms |
| P3 | 15 ms | 6 | 10 ms |

> A. 4  
> B. 5  
> C. 6  
> D. 7

你的答案：**A**  
正确答案：**C，6 次**

调度时间轴：

| 时刻 | 事件 | 被调度进程 | 累计调度次数 |
|---:|---|---:|---:|
| 0 | 系统开始调度 | P0 | 1 |
| 10 | P1、P2 到达，P2 优先级高于 P0 | P2 | 2 |
| 15 | P3 到达，优先级最高 | P3 | 3 |
| 25 | P3 完成 | P2 | 4 |
| 40 | P2 完成 | P0 | 5 |
| 130 | P0 完成 | P1 | 6 |
| 190 | P1 完成，所有进程结束 | 无 | 仍为 6 |

P1 在 10 ms 到达，但其优先级 20 低于正在运行的 P0，所以它的到达本身不会增加一次调度。最终进程结束后没有下一个进程需要选择，也不再计数。

### 第 55 题：分页系统进程切换更新哪些寄存器【错题且存疑】

> **题目：**【2024 统考真题】在支持页式存储管理的系统中，进程切换时操作系统需要执行的操作是（　）。  
> I. 更新程序计数器的值  
> II. 更新栈基址寄存器的值  
> III. 更新页表基址寄存器的值  
> A. 仅 III  
> B. 仅 I、II  
> C. 仅 I、III  
> D. I、II、III

你的答案：**B**  
正确答案：**D，I、II、III**

为什么错：本题是进程切换，不是同一进程内的线程切换。不同进程具有各自的执行位置、栈和地址空间，因此程序计数器、栈基址寄存器和页表基址寄存器都必须换成新进程的值。

与第 09 题对照记忆：

```text
同进程内换线程 → 更新 PC、栈；不换页表
不同进程间切换 → 更新 PC、栈、页表基址
```

### 第 57 题：进程切换时哪个寄存器不用更新【错题】

> **题目：**【2025 统考真题】在采用页式虚拟存储管理方式的系统中，当发生进程上下文切换时，在下列寄存器中，操作系统不需要更新的是（　）。  
> A. 通用寄存器  
> B. 页表基址寄存器  
> C. 程序计数器  
> D. 内核中断向量表基址寄存器

你的原答案：**照片中的黑笔字母被红笔订正线覆盖，无法可靠辨认**  
正确答案：**D，内核中断向量表基址寄存器**

为什么错：通用寄存器、程序计数器和页表基址都属于进程运行现场或地址空间环境，切换进程时需要保存并恢复。中断向量表是全系统共用的内核结构，其基址不会因为运行进程改变而改变。

## 四、做题判断流程

遇到调度和上下文切换题时，依次判断：

1. 题目考的是高级、中级还是低级调度？
2. 当前事件是否会让正在运行的进程停止、阻塞或被抢占？
3. 算法是抢占式还是非抢占式？
4. 优先级数值越大越高，还是越小越高？
5. 切换发生在同一进程的线程之间，还是不同进程之间？
6. 题目要求计算周转时间、等待时间、响应时间，还是调度次数？
7. 是否需要计入已经等待的时间和调度切换开销？

快速判断：

```text
分时系统                 → 时间片轮转
实时系统                 → 抢占式优先级调度
同时到达且求平均周转最短 → 短作业优先
兼顾等待和运行时间       → 高响应比优先
时间片过大               → 时间片轮转退化为 FCFS
时间片用完仍未完成       → 可降低动态优先级
临界区内                 → 仍可能被抢占
同进程线程切换           → 不更新页表基址
跨进程上下文切换         → 更新 PC、栈和页表基址
中断向量表               → 系统公共结构，不随进程切换
```

计算题统一使用：

```text
读题确定规则 → 列到达事件 → 画 CPU 时间轴 → 标完成时刻 → 套公式
```

## 五、自测题

先独立作答，再查看下方答案。

1. 公平性、资源利用率、互斥性和平均周转时间中，哪一项不是调度算法评价指标？
2. 进程处于临界区时，是否一定不能被抢占？
3. 为什么上下文切换不等于把进程的代码和数据写入磁盘？
4. 同一进程内线程切换时，为什么不需要更新页表基址寄存器？
5. FCFS 为什么不利于 I/O 繁忙型作业？
6. 分时系统和实时系统分别偏好什么调度方式？
7. 动态优先级中，为什么时间片用完后可以降低进程优先级？
8. 进程切换时，PC、栈基址和页表基址是否都需要更新？
9. 抢占优先级计算题中，新进程到达是否一定增加一次调度？
10. 调度完成最后一个进程后，系统没有其他就绪进程，是否还要多计一次进程调度？

<details>
<summary>查看答案</summary>

1. 互斥性。它属于进程同步与互斥问题。
2. 不一定。临界区保证对临界资源的互斥访问，不等于禁止 CPU 抢占。
3. 上下文切换只需保存和恢复运行现场；把页面换出到磁盘是存储管理在内存压力等条件下做出的独立决策。
4. 同一进程的线程共享同一个地址空间和页表，只需切换线程私有的 PC、寄存器和栈。
5. 长 CPU 作业可能长期占用处理器，使已经完成 I/O 的短 CPU 进程排队等待，形成护航效应。
6. 分时系统偏好时间片轮转；实时系统通常采用抢占式优先级调度。
7. 时间片用完仍未结束通常表明进程偏 CPU 繁忙，降级可以避免它持续占用处理器，并照顾交互或 I/O 繁忙型进程。
8. 是。不同进程的执行位置、栈和地址空间都不同。
9. 不一定。只有新进程优先级更高并实际引起运行进程变化时，才增加一次调度。
10. 不需要。所有进程结束后没有新的进程被选择运行，不再计一次进程调度。

</details>
