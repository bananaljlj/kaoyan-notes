## 二、核心知识框架

### 1. 程序、进程和 PCB

程序是静态的指令和数据集合；进程是程序的一次执行过程，是动态的。PCB（进程控制块）保存操作系统管理进程所需的信息，是进程存在的唯一标志。

```text
程序：静态文件，本身不占用处理器
进程：程序在某个数据集合上的一次动态执行过程
PCB：操作系统眼中的进程，记录身份、状态、现场和资源信息
```

程序和进程不是简单的一一对应：

- 同一个程序运行多次，可以形成多个不同进程；
- 一个进程在生命周期中可以先后执行多个程序，例如通过 `exec` 替换程序映像；
- 一次程序执行也可能通过创建子进程产生多个进程；
- 一个进程在同一时刻只能执行一个程序映像。

### 2. 并发进程的特征

| 特征   | 含义                                     |
| ------ | ---------------------------------------- |
| 动态性 | 进程具有创建、运行、暂停和终止的生命周期 |
| 并发性 | 多个进程在一段时间内交替向前推进         |
| 独立性 | 进程是独立获得资源和接受调度的基本单位   |
| 异步性 | 进程按不可预知的速度推进                 |

多个并发进程如果共享变量且缺少同步，操作结果会受执行次序和相对速度影响。同样的输入可能得到不同结果，表现为运行结果的不可再现性。

注意：进程的生命周期不是“连续占用 CPU”的过程。进程会在运行态、就绪态和阻塞态之间转换，所以其推进具有间断性。

### 3. 进程的基本状态及转换

```text
                 调度
         就绪态 ───────→ 运行态
           ↑               │  │
           │               │  └── 等待事件或资源 ──→ 阻塞态
           │               │                         │
           └── 事件完成 ───┴─────────────────────────┘
                  运行态被抢占：运行态 → 就绪态
```

更准确地看四种转换：

| 状态转换         | 直接原因                               | 谁起主要作用             |
| ---------------- | -------------------------------------- | ------------------------ |
| 就绪态 → 运行态 | 调度程序分配处理器                     | 操作系统调度程序         |
| 运行态 → 就绪态 | 时间片用完或被更高优先级进程抢占       | 操作系统/中断            |
| 运行态 → 阻塞态 | 正在运行的进程主动等待 I/O、信号或资源 | 进程通过系统调用主动引起 |
| 阻塞态 → 就绪态 | 等待的事件完成或资源可用               | 外部事件及操作系统唤醒   |

记忆方法：

> 只有“运行 → 阻塞”通常由进程自身主动决定；其余三种基本转换都依赖调度、抢占或事件完成。

“申请处理器但没有得到”意味着进程已经具备运行条件，只是在等待 CPU，因此应处于**就绪态**；“申请某个事件或资源且暂时无法满足”才会进入**阻塞态**。

### 4. 进程创建原语

创建一个新进程通常需要：

1. 申请空白 PCB；
2. 为新进程分配所需资源和地址空间；
3. 初始化 PCB；
4. 将新进程插入就绪队列。

创建原语不会直接把 CPU 分配给新进程。新进程创建完成后先进入就绪队列，何时获得 CPU 由调度程序决定。

可能触发创建进程的典型事件包括：

- 用户登录；
- 作业经高级调度被系统接纳；
- 操作系统为响应用户请求而创建服务进程；
- 用户启动应用程序；
- 现有进程执行创建子进程的系统调用。

### 5. 进程映像：PCB、正文段、堆和栈

按本题采用的简化模型，可以这样判断：

| 区域          | 典型内容                                  | 生命周期                   |
| ------------- | ----------------------------------------- | -------------------------- |
| PCB           | PID、进程状态、优先级、CPU 现场、资源信息 | 与进程相同，由内核管理     |
| 正文/静态区域 | 程序代码、常量、具有静态存储期的数据      | 程序装入时建立             |
| 堆            | `malloc()` 等动态申请的存储空间         | 由程序运行时动态申请和释放 |
| 栈            | 局部变量、函数参数、返回地址和调用现场    | 随函数调用和返回自动变化   |

本题的选项把有初值的全局变量和常量归入正文段。更完整的现代进程地址空间通常还会细分只读正文段、只读常量区、已初始化数据段和未初始化数据段；做 408 选择题时，应先服从题目给出的简化分段模型。

### 6. 原语与原子操作

原语是由若干指令组成、用于完成某个系统功能的不可分割操作。它通常在内核态执行，执行期间不会被并发活动观察到“完成了一半”的中间状态。

```text
原子性 = 要么完全没执行，要么已经全部执行
原子性 ≠ 指令数量少
原子性 ≠ 执行速度一定很快
```

因此，“原语称为原子操作，是因为执行速度非常快”是错误的。原子操作强调的是**不可分割和不受干扰**。

### 7. 进程间通信

常见 IPC（进程间通信）方式包括：

- 共享文件；
- 消息传递；
- 共享内存；
- 管道；
- 信号量等同步机制。

普通进程拥有相互隔离的地址空间，一个进程不能直接随意访问另一个进程的私有地址空间。共享内存之所以可行，是因为操作系统把同一物理存储区域映射到多个进程的地址空间中，它是一种受操作系统控制的共享机制。

共享内存通常具有最高的数据传输速度，因为建立映射后，通信双方可以直接读写共享区域，不必让内核反复复制数据。消息传递、管道等方式通常需要系统调用和数据复制。

### 8. 信号的发送与处理

信号是一种异步通知机制，可由其他进程、进程自身或操作系统内核发送。内核为各种信号规定默认处置方式，例如终止、停止、继续或忽略。

进程通常可以选择：

- 执行系统默认动作；
- 忽略某些信号；
- 为某些信号安装自定义处理函数。

但不是每种信号都允许忽略或捕获。例如 Unix/Linux 中的 `SIGKILL` 和 `SIGSTOP` 不能被捕获、阻塞或忽略，所以“用户可以对每种信号自定义处理函数”是错误的绝对化表述。

待处理信号通常在进程即将从内核态返回用户态时检查并处理。用户态进入内核态只是开始执行系统调用或异常处理，并不是本题所说的常规信号处理检查点。

### 9. 进程与线程

线程是处理器调度和执行的基本单位，进程是资源分配的基本单位。一个进程可以包含一个或多个线程，同一进程的线程共享地址空间和大部分进程资源，但各自保存独立的执行现场。

| 同一进程内线程共享                   | 每个线程私有                    |
| ------------------------------------ | ------------------------------- |
| 地址空间、代码、全局数据、打开的文件 | 线程 ID、程序计数器、寄存器、栈 |

线程具有独立的 CPU 现场，因此可以被单独调度执行；但线程不是独立的资源拥有单位，也没有独立的进程地址空间。同一进程内的线程共享内存，通信通常不必经过系统调用。

线程的主要优点包括提高并发性、节约资源和减小切换开销，但共享地址空间也意味着一个线程的错误可能影响整个进程，因此线程不会增强进程安全性。

### 10. 线程切换与并发

处理器实际执行的是线程。线程切换是否引起进程切换，取决于切换前后的线程是否属于同一进程：

```text
进程 P 的线程 T1 → 进程 P 的线程 T2
只切换线程现场，不更换进程地址空间

进程 P 的线程 T1 → 进程 Q 的线程 T3
既切换线程现场，也要切换进程地址空间等上下文
```

所以，“线程切换一定不会引起进程切换”和“线程切换一定引起进程切换”都不准确，正确说法是**可能引起**。

无论线程属于同一进程还是不同进程，它们都可能并发执行；在多处理器系统中，不同线程还可能真正并行运行。多线程尤其适合具有多个相对独立任务的场景，如 Web 请求处理、矩阵分块计算和 GUI 应用中的输入、计算、跟踪任务。

### 11. 用户级线程、内核级线程与映射模型

| 对比项               | 用户级线程（ULT）            | 内核级线程（KLT）                |
| -------------------- | ---------------------------- | -------------------------------- |
| 管理者               | 用户态线程库                 | 操作系统内核                     |
| 内核是否感知每个线程 | 否                           | 是                               |
| 调度单位             | 内核调度进程，线程库调度线程 | 内核直接调度线程                 |
| 切换开销             | 较小，通常不进入内核         | 较大，需要内核参与               |
| 某线程阻塞的影响     | 可能使整个进程阻塞           | 同进程其他线程仍可运行           |
| 多处理器并行         | 纯用户级模型通常受限         | 可由内核把多个线程调度到多个 CPU |

用户级线程的创建、撤销、同步和调度通常由线程库完成，不需要内核直接干预。线程同步或线程主动让出处理器等线程库能够感知的事件，可能触发用户级线程切换；系统调用、I/O 请求和异常首先由内核按进程处理，内核并不知道应切换到该进程的哪个用户级线程。

常见映射模型：

| 模型   | 用户线程与内核线程的关系       | 主要特点                                                 |
| ------ | ------------------------------ | -------------------------------------------------------- |
| 多对一 | 多个用户线程映射到一个内核线程 | 管理简单，但一个线程阻塞可导致整个进程阻塞，不能多核并行 |
| 一对一 | 每个用户线程对应一个内核线程   | 并发性好，但创建和管理开销较大                           |
| 多对多 | 多个用户线程复用多个内核线程   | 兼顾灵活性和并发性                                       |

### 12. 合作进程、共享数据与管道

合作进程可以通过文件系统、共享内存和消息传递交换数据，但不能直接依靠高级语言中的普通全局变量通信。普通全局变量只在所属进程的虚拟地址空间内可见；即使两个进程运行相同程序，它们也各有自己的全局变量副本。

管道是内核维护的有限大小缓冲区。普通匿名管道通常是单向的；若要双向通信，通常需要建立两个管道或使用其他双向 IPC 机制。

| 管道状态             | 读操作   | 写操作                     |
| -------------------- | -------- | -------------------------- |
| 管道为空且仍有写端   | 可能阻塞 | 可以写入                   |
| 管道已满             | 可以读出 | 可能阻塞                   |
| 没有写端且数据已读完 | 返回 EOF | -                          |
| 没有读端             | -        | 写入通常失败并可能触发信号 |

管道容量由内核缓冲区大小限制，不是只受磁盘容量限制；一个管道也不要求只能有一个读进程或一个写进程。

### 第 02 题：进程间交换数据的途径【存疑】

> **题目：** 进程之间交换数据不能通过（　）途径进行。
> A. 共享文件
> B. 消息传递
> C. 访问进程地址空间
> D. 访问共享存储区

你的作答：**未填写**
正确答案：**C，访问进程地址空间**

普通进程的私有地址空间彼此隔离，不能直接访问另一个进程的地址空间。共享文件、消息传递和共享存储区都是操作系统提供或控制的合法通信途径。

易错点在于 C 和 D 看起来都涉及“访问内存”，但两者本质不同：

```text
直接访问另一个进程的私有地址空间 → 破坏隔离，不允许
访问双方共同映射的共享存储区     → 合法 IPC
```

### 第 05 题：并发进程的特性【存疑但答对】

> **题目：** 下列关于并发进程特性的叙述中，正确的是（　）。
> A. 进程是一个动态过程，其生命周期是连续的
> B. 并发进程执行完毕后，一定能够得到相同的结果
> C. 并发进程对共享变量的操作结果与执行速度无关
> D. 并发进程的运行结果具有不可再现性

你的答案：**D**
正确答案：**D**

你最终判断正确。并发进程以不可预知的相对速度推进，如果多个进程对共享数据的访问缺少同步，运行次序不同就可能产生不同结果，因此具有不可再现性。

- A 错：进程虽然是动态过程，但会不断经历暂停和恢复，推进是间断的。
- B 错：存在竞争条件时，结果不一定相同。
- C 错：对共享变量的结果往往与执行次序和相对速度有关。

### 第 06 题：调度与进程状态【错题且存疑】

> **题目：** 下列关于进程的叙述中，正确的是（　）。
> A. 进程获得处理器运行是通过调度得到的
> B. 优先级是进程调度的重要依据，一旦确定就不能改动
> C. 在单处理器系统中，任何时刻都只有一个进程处于运行态
> D. 进程申请处理器而得不到满足时，其状态变为阻塞态

你的答案：**D**
正确答案：**A**

为什么错：你把“等待处理器”误认为“阻塞”。等待 CPU 的进程已经具备运行条件，应处于就绪态；阻塞态表示进程还在等待 I/O、资源或某个事件，即使马上给它 CPU 也无法继续执行。

- A 对：就绪进程必须经调度程序选中，才能获得处理器。
- B 错：动态优先级可以在运行过程中调整。
- C 表述过强：单处理器系统任一时刻**至多**有一个进程运行，也可能因系统空闲而没有进程运行。
- D 错：没有获得处理器时应继续等待在就绪队列中。

### 第 08 题：进程创建原语的工作【错题】

> **题目：** 下列任务中，（　）不是由进程创建原语完成的。
> A. 申请 PCB 并初始化
> B. 为进程分配内存空间
> C. 为进程分配 CPU
> D. 将进程插入就绪队列

你的答案：**D**
正确答案：**C，为进程分配 CPU**

为什么错：创建原语完成的是“建立一个可被调度的新进程”，所以申请和初始化 PCB、分配必要资源、插入就绪队列都属于创建过程。真正把 CPU 分配给某个就绪进程，是处理器调度程序的职责。

记忆方法：

> 创建原语负责“让它有资格排队”，调度程序负责“决定何时上 CPU”。

### 第 09 题：程序与进程的关系【存疑但答对】

> **题目：** 下列关于进程和程序的叙述中，错误的是（　）。
> A. 一个进程在其生命周期中可执行多个程序
> B. 一个进程在同一时刻可执行多个程序
> C. 一个程序的多次运行可形成多个不同的进程
> D. 一个程序的一次执行可产生多个进程

你的答案：**B**
正确答案：**B**

你最终判断正确。一个进程可以在生命周期中先后执行不同程序，但在同一时刻只有一个当前程序映像。一个程序可被多次启动而形成多个进程，一次执行也可能创建子进程，所以程序和进程并不是一一对应关系。

### 第 10 题：哪些操作会创建新进程【错题】

> **题目：** 下列选项中，导致创建新进程的操作是（　）。
> I. 用户登录
> II. 高级调度发生时
> III. 操作系统响应用户提出的请求
> IV. 用户打开了一个浏览器程序
> A. 仅 I 和 IV
> B. 仅 II 和 IV
> C. I、II 和 IV
> D. 全部

你的答案：**C**
正确答案：**D，全部**

为什么错：你漏掉了 III。操作系统在响应用户请求时，可能创建一个进程来完成相应服务。其余三项也都会触发进程创建：登录后要建立用户会话进程；高级调度接纳作业时会为其建立进程；启动浏览器会创建应用进程。

这类题不能只判断“用户是否直接点击了程序”，而要看该事件是否需要系统建立一个新的执行实体。

### 第 22 题：进程映像各部分存放的内容【存疑】

> **题目：** 若一个进程实体由 PCB、共享正文段、数据堆段和数据栈段组成，请指出下列 C 语言程序中的内容及相关数据结构各位于哪一段中。
> I. 全局赋值变量
> II. 未赋值的局部变量
> III. 函数调用实参传值
> IV. 用 `malloc()` 要求动态分配的存储区
> V. 常量值（如 1995、`"string"`）
> VI. 进程的优先级

### 第 27 题：进程能够自行决定的状态转换【错题】

> **题目：** 进程自身决定（　）。
> A. 从运行态到阻塞态
> B. 从运行态到就绪态
> C. 从就绪态到运行态
> D. 从阻塞态到就绪态

你的答案：**D**
正确答案：**A，从运行态到阻塞态**

为什么错：运行中的进程可以主动发起 I/O 或等待某个事件，从而主动进入阻塞态。阻塞态进程不能靠自己继续执行，也就不能自行决定转为就绪态；它必须等待事件完成后由操作系统唤醒。

- 运行 → 就绪：通常由时间片用完或抢占引起；
- 就绪 → 运行：由调度程序决定；
- 阻塞 → 就绪：由等待事件完成引起；
- 运行 → 阻塞：由进程主动等待引起。

### 第 28 题：原语为什么具有原子性【存疑但答对】

> **题目：** 下列关于原语操作的叙述中，错误的是（　）。
> A. 操作系统使用原语对进程进行管理和控制
> B. 原语在执行过程中不允许被中断
> C. 原语在内核态下执行，常驻内存
> D. 原语被定义为“原子操作”，意思是其执行速度非常快

你的答案：**D**
正确答案：**D**

你最终判断正确。原子操作的关键是执行过程不可分割，外界只能看到“尚未执行”或“已经全部执行”两种状态，而不是执行速度快。一个原语即使包含较多步骤，只要整体不可被并发活动打断和观察，仍然具有原子性。

### 第 31 题：哪些信号可以自定义处理【错题】

> **题目：** 下列关于信号发送和处理的描述中，错误的是（　）。
> A. 一个进程可以给自己发送信号
> B. 操作系统的内核可以给进程发送信号
> C. 操作系统的内核对每种信号都有默认处理程序
> D. 用户可以对每种信号自定义处理函数

你的答案：**C**
正确答案：**D**

为什么错：内核会为信号规定默认处置方式，所以 C 正确；但用户不能对每种信号都安装自定义处理函数。某些用于强制终止或停止进程的信号必须由内核掌控，例如 `SIGKILL` 和 `SIGSTOP`，不能被捕获或忽略。

看到“每种”“全部”“一定”等词时要特别警惕。D 的错误不在于信号不能自定义处理，而在于把“某些信号”扩大成了“每种信号”。

### 第 32 题：信号的检查与处理时机【存疑但答对】

> **题目：** 下列关于信号处理的描述中，错误的是（　）。
> A. 当进程从内核态转换为用户态时，会检查是否有待处理的信号
> B. 当进程从用户态转换为内核态时，也会检查是否有待处理的信号
> C. 操作系统对某些信号的处理是可以忽略的
> D. 操作系统允许进程通过系统调用，自定义某些信号的处理程序

你的答案：**B**
正确答案：**B**

你最终判断正确。待处理信号通常在进程即将返回用户态时检查，因为自定义信号处理函数需要在用户态执行。用户态刚进入内核态时，CPU 要先处理导致陷入内核的系统调用、中断或异常，并不是题目所说的常规信号处理时机。

C 和 D 中都使用了“某些”，没有把范围说成全部，因此是正确表述。

### 第 33 题：线程切换是否引起进程切换【错题】

> **题目：** 下面的叙述中，正确的是（　）。
> A. 引入线程后，处理器只能在线程间切换
> B. 引入线程后，处理器仍在进程间切换
> C. 线程的切换，不会引起进程的切换
> D. 线程的切换，可能引起进程的切换

你的答案：**C**
正确答案：**D**

为什么错：如果切换到同一进程内的另一个线程，只需切换线程私有的执行现场，不需要更换进程地址空间；如果切换到另一个进程中的线程，就必须连同进程上下文一起切换。因此，线程切换**可能**引起进程切换，但不是必然引起。

```text
同一进程内换线程 → 不换进程
跨进程换线程     → 同时换进程
```

### 第 34 题：线程拥有什么【存疑但答对】

> **题目：** 下列关于线程的叙述中，正确的是（　）。
> A. 线程包含 CPU 现场，可以独立执行程序
> B. 每个线程都有自己独立的地址空间
> C. 每个进程只能包含一个线程
> D. 同一进程中的线程间通信也必须使用系统调用

你的答案：**A**
正确答案：**A**

你最终判断正确。线程必须保存程序计数器、寄存器和栈等执行现场，才能被单独调度和恢复执行。

- B 错：同一进程的线程共享进程地址空间。
- C 错：一个进程可以包含多个线程。
- D 错：同一进程的线程可直接读写共享地址空间中的数据，通信不一定需要系统调用。

### 第 36 题：不同进程中的线程能否并发【错题】

> **题目：** 下面的叙述中，正确的是（　）。
> A. 同一进程内的线程可并发执行，不同进程的线程只能串行执行
> B. 同一进程内的线程只能串行执行，不同进程的线程可并发执行
> C. 同一进程或不同进程内的线程都只能串行执行
> D. 同一进程或不同进程内的线程都可以并发执行

你的答案：**A**
正确答案：**D**

为什么错：并发的关键是在一段时间内交替推进，不要求线程属于同一个进程。同一进程的多个线程可以并发，不同进程中的线程也可以并发；在多处理器上，它们还可能同时并行执行。

### 第 37 题：线程不能带来的优点【存疑但答对】

> **题目：** 下列选项中，（　）不是线程的优点。
> A. 提高系统并发性
> B. 节约系统资源
> C. 切换开销小
> D. 增强进程安全性

你的答案：**D**
正确答案：**D**

你最终判断正确。线程共享进程的地址空间和资源，创建和切换通常比进程轻量，也能提高并发性。但这种共享同时降低了故障隔离能力：一个线程错误写内存，可能破坏整个进程，因此不能说线程增强了进程安全性。

### 第 39 题：多线程适用场景【错题】

> **题目：** 在下列描述中，（　）并不是多线程系统的特长。

> B. Web 服务器利用线程响应 HTTP 请求

你的答案：**B**
正确答案：**C**

为什么错：Web 服务器的多个请求相对独立，适合由多个线程并发处理。矩阵分块计算和 GUI 中不同任务也适合并行或并发。键盘是由操作系统统一管理的共享设备，驱动程序通常集中接收并分发输入；为每个应用在键盘驱动中单独建立线程既没有必要，也不能体现多线程的典型优势。

### 第 42 题：合作进程如何交换数据【错题且存疑】

> **题目：** 两个合作进程（Cooperating Processes）无法利用（　）交换数据。
> A. 文件系统
> B. 共享内存
> C. 高级语言程序设计中的全局变量
> D. 消息传递系统

你的答案：**A**
正确答案：**C，高级语言程序设计中的全局变量**

为什么错：不同进程具有相互隔离的虚拟地址空间。即使两个进程运行同一程序，它们的普通全局变量也是各自独立的副本，不能直接用于交换数据。文件、共享内存和消息传递都是操作系统支持的跨进程通信机制。

这道题与第 02 题可以一起记忆：

```text
同一进程的线程 → 可以共享全局变量
不同合作进程   → 必须使用 IPC，不能直接共享普通全局变量
```

### 第 46 题：进程被唤醒意味着什么【错题】

> **题目：** 一个进程被唤醒，意味着（　）。
> A. 该进程可以重新竞争 CPU
> B. 该进程的优先级变大
> C. 该进程的 PCB 移动到就绪队列之首
> D. 该进程变为运行态

你的答案：**D**
正确答案：**A**

为什么错：唤醒发生在等待事件已经完成时，进程由阻塞态转为就绪态。它只是重新具备运行条件，可以参与 CPU 竞争，并不会立即进入运行态。是否排到就绪队列首部以及何时运行，由调度算法决定，优先级也不一定变化。

### 第 49 题：内核级线程相对用户级线程的特点【存疑但答对】

### 第 52 题：什么会触发用户级线程切换【错题且存疑】

> **题目：** 下列选项中，可能导致用户级线程切换的事件是（　）。

> B. I/O 请求
> C. 异常处理
> D. 线程同步

你的答案：**B**
正确答案：**D，线程同步**

为什么错：用户级线程由线程库管理，内核看不到进程内部的各个用户线程。线程执行同步操作时，线程库能够发现当前线程需要等待，从而切换到另一个用户线程。系统调用、I/O 请求和异常由内核按进程处理；在纯用户级线程模型中，阻塞系统调用还可能使整个进程阻塞，而不是由内核切换其内部用户线程。

### 第 53 题：用户级线程是否需要内核干预【存疑但答对】

> B. 用户级线程只有在创建和调度时需要内核的干预

### 第 58 题：创建新进程的事件【错题】

> **题目：**【2010 统考真题】下列选项中，导致创建新进程的操作是（　）。
> I. 用户登录成功
> II. 设备分配
> III. 启动程序执行
> A. 仅 I 和 II
> B. 仅 II 和 III
> C. 仅 I 和 III
> D. I、II、III

你的答案：**D**
正确答案：**C，仅 I 和 III**

为什么错：用户登录后，系统需要建立相应的用户进程；启动程序执行也要创建承载该程序的进程。设备分配只是把设备资源交给已有进程使用，不需要因此创建一个新进程。

判断这类题时要问：操作是否需要一个新的独立执行实体？资源分配本身不等于进程创建。

### 第 61 题：磁盘读操作完成后的状态变化【存疑】

> **题目：**【2014 统考真题】一个进程的读磁盘操作完成后，操作系统针对该进程必做的是（　）。
> A. 修改进程状态为就绪态
> B. 降低进程优先级
> C. 给进程分配用户内存空间
> D. 增加进程时间片大小

你的作答：**未填写**
正确答案：**A，修改进程状态为就绪态**

读磁盘时，进程因等待 I/O 而处于阻塞态；磁盘操作完成意味着等待事件已经发生，操作系统必须唤醒该进程，使其进入就绪态。它之后还要等待调度，并不一定立即获得 CPU。优先级、内存空间和时间片大小都不必因此改变。

### 第 62 题：管道通信的阻塞语义【错题】

> **题目：**【2014 统考真题】下列关于管道（Pipe）通信的叙述中，正确的是（　）。
> A. 一个管道可实现双向数据传输
> B. 管道的容量仅受磁盘容量大小限制
> C. 进程对管道进行读操作和写操作都可能被阻塞
> D. 一个管道只能有一个读进程或一个写进程对其操作

你的答案：**B**
正确答案：**C**

- B 错：容量受内核管道缓冲区限制。
- D 错：管道可以存在多个读端或写端，操作系统负责同步和协调。

## 四、做题判断流程

遇到进程概念、状态和机制题时，可以按下面的顺序判断：

1. 当前主体是静态程序、动态进程，还是内核中的 PCB？
2. 进程当前是否已经具备继续运行的条件？
3. 状态变化是进程主动请求，还是由调度、抢占或外部事件引起？
4. 题目问的是创建进程，还是给就绪进程分配 CPU？
5. 数据属于内核管理信息、静态内容、动态内存还是函数调用现场？
6. 线程切换前后的两个线程属于同一进程还是不同进程？
7. 线程由用户态线程库管理，还是由内核直接管理和调度？
8. 通信双方是同一进程内的线程，还是地址空间隔离的两个进程？
9. 题目中的“每种”“一定”“任何时刻都只有一个”等绝对化表述是否过强？

快速判断：

```text
等待 CPU                   → 就绪态
等待 I/O、资源或事件       → 阻塞态
进程主动引起的基本转换     → 运行态到阻塞态
创建完成                   → 插入就绪队列
真正获得 CPU               → 由调度程序决定
malloc                     → 堆
局部变量、函数参数         → 栈
优先级、进程状态、CPU 现场 → PCB
原子操作                   → 不可分割，不等于速度快
共享内存                   → 受控共享，不是访问他人私有空间
自定义信号处理             → 仅适用于允许捕获的信号
同一进程内线程切换         → 不引起进程切换
跨进程的线程切换           → 同时引起进程切换
用户级线程创建和调度       → 线程库完成
内核级线程调度             → 操作系统内核完成
进程被唤醒                 → 阻塞态变为就绪态
跨进程交换数据             → 使用 IPC，不能直接用普通全局变量
管道为空时读、管道满时写   → 都可能阻塞
```

## 五、自测题

先独立作答，再查看下方答案。

1. 一个进程等待 CPU 时处于什么状态？等待磁盘 I/O 完成时又处于什么状态？
2. 四种基本状态转换中，哪一种通常由进程自身主动引起？
3. 进程创建原语为什么只把进程插入就绪队列，而不直接为它分配 CPU？
4. 同一个程序能否对应多个进程？一个进程能否在生命周期中先后执行多个程序？
5. `malloc()` 申请的空间、普通局部变量和进程优先级分别位于哪里？
6. 原子操作中的“原子”为什么与执行速度无关？
7. 为什么共享内存可以用于 IPC，而直接访问另一个进程的地址空间不可以？
8. 用户是否可以为所有信号安装自定义处理函数？
9. 待处理信号通常在进入内核态时检查，还是在返回用户态前检查？
10. 线程切换在什么情况下会同时引起进程切换？
11. 同一进程中的线程共享哪些内容，各自私有哪些执行信息？
12. 用户级线程和内核级线程分别由谁调度？哪一种切换开销通常更小？
13. 为什么两个合作进程不能直接用普通全局变量交换数据？
14. 一个阻塞进程被唤醒后立即进入运行态吗？
15. 管道在什么情况下会使读进程或写进程阻塞？

<details>
<summary>查看答案</summary>

1. 等待 CPU 时处于就绪态；等待磁盘 I/O 完成时处于阻塞态。
2. 运行态到阻塞态，进程通过系统调用主动等待事件或资源。
3. 创建原语只负责建立进程并使其具备被调度的资格；CPU 的分配必须由调度程序统一决定。
4. 可以。一个程序的多次运行可形成多个进程；一个进程也可以在生命周期中先后执行多个程序。
5. `malloc()` 空间在堆，普通局部变量在栈，进程优先级在 PCB。
6. “原子”表示不可分割，外界不能观察到中间状态，与操作本身需要执行多久没有必然关系。
7. 共享内存是由操作系统把同一存储区域合法映射给多个进程；另一个进程的私有地址空间受隔离和保护，不能直接访问。
8. 不可以。某些信号不能被捕获或自定义处理，例如 `SIGKILL`、`SIGSTOP`。
9. 通常在进程从内核态返回用户态前检查。
10. 当切换后的线程属于另一个进程时，需要同时切换进程地址空间等上下文，因而引起进程切换。
11. 共享地址空间、代码、全局数据和打开的文件；每个线程私有线程 ID、程序计数器、寄存器和栈。
12. 用户级线程由用户态线程库调度，内核级线程由操作系统内核调度；用户级线程切换开销通常更小。
13. 两个进程的虚拟地址空间相互隔离，普通全局变量是各自独立的副本，跨进程交换必须借助 IPC。
14. 不会。被唤醒后由阻塞态变为就绪态，还要等待调度才能运行。
15. 管道为空且仍有写端时，读操作可能阻塞；管道已满时，写操作可能阻塞。

</details>
