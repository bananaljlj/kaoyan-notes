## 二、控制器的基本任务与组成

### 1. 控制器的任务

控制器按照机器指令的要求，在正确的时间发出控制信号，使各部件完成相应的微操作。

一条机器指令的执行过程可概括为：

```text
取指令 → 分析指令 → 执行指令
```

控制器必须回答两个问题：

1. 当前应该完成哪些微操作？
2. 这些微操作应在什么时刻完成？

### 2. 控制部件的典型组成

- **PC（程序计数器）**：保存下一条机器指令的地址。
- **IR（指令寄存器）**：保存当前正在执行的机器指令。
- **指令译码器/操作控制器**：分析操作码并形成控制依据。
- **时序系统**：产生节拍、脉冲等时序信号。

**【未掌握·题18】状态条件寄存器的归属**

- 状态条件寄存器保存零、进位、溢出、符号等标志。
- 它通常归入**运算器**，但其输出会送给控制器，作为条件转移和控制信号形成的依据。
- “给控制器提供输入”不等于“属于控制器”。判断部件归属时要区分这两件事。

## 三、硬布线控制器与微程序控制器

| 比较项 | 硬布线/组合逻辑控制器 | 微程序控制器 |
|---|---|---|
| 实现方法 | 组合逻辑电路直接产生控制信号 | 读取控制存储器中的微指令产生控制信号 |
| 速度 | **快** | 较慢，需要读取微指令 |
| 修改与扩展 | 困难 | **容易、灵活** |
| 适用倾向 | RISC、强调高速的系统 | CISC、指令复杂且重视规整性的系统 |
| 设计特点 | 电路复杂，调试修改不方便 | 结构规整，便于维护和扩展 |

### 1. 硬布线控制信号的形成

硬布线控制器中，某个控制信号可抽象表示为：

$$
C_i=f(\text{指令译码信号},\ \text{时序信号},\ \text{状态/条件信号})
$$

- **指令译码信号**：说明“要做什么”。
- **时序信号**：说明“什么时候做”。
- **状态/条件信号**：说明“当前是否满足条件”。

**【未掌握·题2】操作码必须先译码。地址码通常用于指出操作数位置，不是形成微操作控制信号的主要直接依据；只考虑操作码和条件码又漏掉了时序。**

### 2. 微程序控制器为什么较慢

执行机器指令时，还要从**控制存储器 CS** 中逐条读取微指令，因此比硬布线控制器多出取微指令和形成下地址的时间。

记忆：

```text
硬布线：快，但难改
微程序：慢，但灵活
```

## 四、微程序控制的概念层级

```text
一条机器指令
    ↓ 由一个微程序解释执行
一个微程序
    ↓ 由若干条微指令组成
一条微指令
    ↓ 包含若干个可同时发出的微命令
一个微命令（控制信号）
    ↓ 控制完成
一个微操作
```

### 易混概念

| 概念 | 含义 |
|---|---|
| 微操作 | 数据通路中最基本的操作，如 `PC→MAR`、`MDR→IR`、寄存器加 1 |
| 微命令 | 控制部件发出的控制信号，是微操作的控制依据 |
| 微指令 | 在一个微指令周期内发出的一组微命令，以及产生后继微地址的信息 |
| 微程序 | 完成某一机器指令功能的一串微指令 |

通常，一条机器指令对应一个微程序，一个微程序周期对应一个**指令周期**。

**【易错】指令周期不等于 CPU 时钟周期。** 一个指令周期通常包含多个时钟周期；微程序中也通常包含多条微指令。

### CPU 能直接执行什么

| 类型 | 是否可由 CPU/内部硬件直接执行 | 原因 |
|---|---|---|
| 机器指令 | 是 | 是 CPU 指令系统中规定的二进制指令 |
| 微指令 | 是（微程序控制器内部） | 从控制存储器取出后，由控制硬件解释并发出微命令 |
| 汇编指令 | 否 | 必须由汇编器翻译成机器指令 |
| 伪指令 | 否 | 是提供给汇编器的命令，不属于机器指令系统 |

**【未掌握·题27】汇编指令与机器指令通常是一一对应的助记表示，但“语义对应”不等于“CPU 能直接执行”。伪指令更不会在运行时交给 CPU 执行。**

## 五、微程序控制器的组成与工作过程

### 1. 主要部件

- **控制存储器 CS**：存放全部微程序，位于 CPU 内部，通常用 ROM 实现。
- **微地址寄存器 CMAR / μPC**：保存当前或下一条微指令地址。
- **微指令寄存器 CMDR / μIR**：保存当前微指令。
- **微地址形成部件/顺序逻辑**：根据微指令下地址、条件标志和机器指令操作码等形成后继微地址。

> 名称可能因教材而异：CMAR 常称微程序计数器 μPC，CMDR 常称微指令寄存器 μIR。

### 2. 基本工作流程

```text
机器指令操作码
      ↓ 形成该机器指令的微程序入口地址
CMAR / μPC
      ↓ 按地址访问控制存储器
控制存储器 CS
      ↓ 读出微指令
CMDR / μIR
      ├─ 操作控制字段 → 发出微命令
      └─ 顺序控制字段 → 形成下一条微指令地址
```

### 3. 控制存储器与主存储器

| 比较项 | 主存储器 MM | 控制存储器 CS |
|---|---|---|
| 位置 | CPU 外、主机内部 | CPU 内部的控制器中 |
| 内容 | 机器指令和数据 | 微指令 |
| 访问方式 | 按地址访问 | **同样按地址访问** |
| 常见介质 | RAM 和 ROM | 通常为 ROM |

**【易错】CS 不是按内容访问的相联存储器。**

### 4. 控制存储器容量

若微地址寄存器为 $m$ 位、微指令字长为 $n$ 位，则控制存储器最大容量为：

$$
2^m \times n\ \text{bit}
$$

例如，`μPC=8 位`、`μIR=32 位`：

$$
2^8\times32\text{ bit}=8192\text{ bit}=1024\text{ B}=1\text{ KB}
$$

## 六、微指令的格式与编码

一条微指令通常包含两大部分：

```text
┌──────────────┬────────────────┐
│ 操作控制字段 │ 顺序控制/下地址字段 │
└──────────────┴────────────────┘
   发出哪些微命令       下一条微指令在哪
```

### 1. 微指令结构设计的目标

- 有利于提高微程序执行速度。
- 有利于充分利用数据通路的并行性。
- 微指令字长尽量短，以减少控制存储器容量。
- 具有一定灵活性，便于设计和扩展。

**【未掌握·题4】“增大控制存储器容量”不是设计目标。微指令设计通常希望在满足速度和并行性的前提下，减少所需容量。**

### 2. 直接编码方式

- 每一位直接对应一个微命令。
- 不需要译码，速度快。
- 可同时置多个控制位，并行性强。
- 控制字段很长，编码效率低。

### 3. 字段直接编码方式

1. 把**互斥性微命令**分在同一字段。
2. 每个字段经译码后选择其中一个微命令。
3. 不同字段中的相容性微命令可以并行发出。
4. 每个字段通常保留一种编码表示“本字段不发出微命令”。

若某字段有 $N$ 个互斥性微命令，至少需要：

$$
k=\lceil\log_2(N+1)\rceil
$$

这里的 `+1` 是为“不操作”状态保留编码。

例：

- 4 个互斥性微命令：$\lceil\log_2(4+1)\rceil=3$ 位，不是 2 位。
- 9 个互斥性微命令：$\lceil\log_2(9+1)\rceil=4$ 位。

### 4. 字段间接编码方式

某字段的含义依赖另一个字段的译码结果。它能进一步缩短微指令字长，但译码更复杂、速度更慢。

### 5. 相容性与互斥性微命令

- **相容性微命令**：能在同一微周期同时执行，不发生资源冲突。
- **互斥性微命令**：不能在同一微周期同时执行。

**【未掌握·题14】判断方法：看它们同时执行是否争用同一个硬件资源。若可能造成总线冲突、同一寄存器被多个来源同时写入等问题，就是互斥性微命令。**

记忆：

```text
能同时 → 相容
会冲突 → 互斥
同字段 → 放互斥命令
跨字段 → 可并行发出相容命令
```

## 七、水平型与垂直型微指令

| 比较项 | 水平型微指令 | 垂直型微指令 |
|---|---|---|
| 编码方式 | 直接编码或字段直接编码 | 设置微操作码，采用类似机器指令的编码 |
| 字长 | 长 | 短 |
| 并行性 | **强**，一条可完成多个微操作 | 弱，一条通常完成一个基本操作 |
| 微程序长度 | 短 | 长 |
| 执行速度 | 快 | 慢 |
| 灵活性 | 相对较低 | 相对较高，规整、易编程 |

**【未掌握·题13】垂直型微指令的正确方向是：**

```text
微操作码（编码形式） → 译码器 → 控制信号
```

因此应说“采用微操作码”或“微操作码经译码产生控制信号”，不能说“控制信号经过编码产生”。

## 八、微地址的形成与位数计算

### 1. 微程序入口地址

执行完公共取指微程序后，机器指令已经进入 IR。通常用机器指令的**操作码字段**经过映射，形成该机器指令所对应微程序的入口地址。

**【易错】入口地址来自机器指令操作码，不是机器指令地址码，也不是当前微指令的微操作码。**

### 2. 后继微地址形成方式

- **增量方式**：`μPC ← μPC + 1`，顺序执行下一条微指令。
- **断定方式/下地址字段法**：微指令直接给出后继微地址。
- **条件转移方式**：根据状态标志选择不同的后继微地址。
- **入口映射方式**：根据机器指令操作码形成对应微程序的入口。

采用断定方式时，微指令下地址字段必须能够表示控制存储器中可能访问的全部微地址。

### 3. 下地址字段位数

若共有 $N$ 条需要编址的微指令，则至少需要：

$$
k=\lceil\log_2N\rceil
$$

**【未掌握·题23】原题计算：**

- 32 条机器指令；
- 公共取指微程序含 2 条微指令；
- 每条机器指令对应的执行微程序平均含 4 条微指令。

微指令总数为：

$$
N=2+32\times4=130
$$

因为：

$$
2^7=128<130\le 256=2^8
$$

所以下地址字段至少为 **8 位**。

错误思路是直接计算 $\log_2 32$，这只给机器指令编号，不能给 130 条微指令编址。

### 4. 计算题统一步骤

1. 先确定要编址的是机器指令、微指令、寄存器还是存储单元。
2. 统计所有需要独立地址的对象，注意公共取指微程序是否另计。
3. 用 $\lceil\log_2N\rceil$ 向上取整。
4. 检查是否漏掉“不操作”编码；只有字段编码题通常要计算 `N+1`。

## 九、错题中的高频陷阱

1. **把“操作码”与“操作码译码信号”混为一谈**  
   硬布线控制逻辑真正使用的是译码后的结果，并且还必须结合时序和状态条件。

2. **把“编码”和“译码”的方向说反**  
   微指令中保存的是编码，编码经过译码才形成控制信号。

3. **把控制器使用的状态信号提供者误判为控制器组成部分**  
   状态寄存器向控制器反馈信息，但通常属于运算器。

4. **看到 32 条机器指令就直接算 $\log_2 32$**  
   先问清楚字段要表示的是机器指令入口，还是所有微指令地址。

5. **把“汇编助记符与机器指令对应”理解成“CPU 可直接执行汇编指令”**  
   CPU 只能处理编码后的机器指令；汇编指令和伪指令都要由汇编器处理。

6. **忽略字段编码中的“不操作”状态**  
   $N$ 个互斥命令通常要按 $N+1$ 种状态计算位数。

## 十、考前速记

```text
硬布线控制信号 = 指令译码 + 时序 + 状态条件

机器指令 → 微程序 → 微指令 → 微命令 → 微操作

控制存储器：CPU 内、存微指令、通常 ROM、按地址访问

水平型：字长长、并行强、微程序短、速度快
垂直型：微操作码、需译码、字长短、并行弱、微程序长

相容命令能同时，互斥命令会冲突
字段直接编码：同字段放互斥命令，位数按 ceil(log2(N+1))

微地址位数：先数全部微指令，再算 ceil(log2 N)

CPU：执行机器指令；微程序硬件内部执行微指令
汇编指令、伪指令：不能直接执行
```
