# 输入输出系统：408 大纲框架与真题复盘

> 本文按 408 计算机组成原理中输入/输出系统的常见大纲范围组织：外部设备、I/O 接口、I/O 方式（程序查询、中断、DMA），并串起相关的总线、磁盘与操作系统知识。真题部分只概述可核对的年份、题号和考法；计算演练如标有“自编”，就不是原题。**备考当年若有大纲调整，以当年正式考试大纲为准。**

## 一、先抓住一条主线

CPU 想从设备拿到数据，需要连续解决三个问题：

```text
设备是谁？         -> 用接口的端口地址识别、下达命令
设备什么时候就绪？ -> 反复查询，或让设备发中断
谁搬运大量数据？   -> CPU 逐次搬运，或由 DMA 控制器搬运
```

完整的数据路径可以想成：

```text
程序/驱动 -> CPU -> 总线 -> I/O 接口(控制器) -> 外部设备
                       |      数据/状态/控制端口
                       +-> 主存 <--------------+
                              DMA 传送时的数据通路
```

**最重要的区分**：中断解决“何时让 CPU 来处理”；DMA 解决“批量数据由谁搬”。DMA 传完仍通常用中断通知 CPU，二者并不互斥。

## 二、按大纲建立考点地图

| 模块 | 要回答的问题 | 常见考法 |
|---|---|---|
| 外部设备 | 输入、输出、外存有哪些？快慢和数据量如何？ | 为键盘、网卡、磁盘等选择 I/O 方式 |
| I/O 接口（控制器） | 主机怎样识别设备、交换数据、获知状态？ | 区分接口与设备；端口功能、编址 |
| 程序查询 | CPU 何时查一次才不会丢数据？ | 查询间隔、CPU 时间占比 |
| 程序中断 | 谁请求、何时响应、保存什么？ | 中断/异常辨析、优先级、开销 |
| DMA | 谁申请总线，何时中断，CPU 能否访问主存？ | 传送路径、周期挪用、请求次数、CPU 占比 |

**范围边界**：总线、磁盘结构与操作系统设备管理有各自的章节，但历年综合题会把它们同 I/O 放在一起。不要把“磁盘平均访问时间”和“DMA 传送时间”混作一个量。

### 2.1 外部设备：选择方式时看数据量与速率

- 输入设备如键盘、鼠标：通常事件零散、数据量小，适合中断通知。
- 输出设备如显示器、打印机：实现方式依具体控制器；不能只凭“输出设备”断言一定使用哪种方式。
- 外存及高速设备如 SSD、网卡：常需大块、高速传输，适合 DMA。
- “适合 DMA”是典型场景选择题，不是“键盘在任何硬件上都不可能 DMA”的绝对命题。

### 2.2 接口、端口和设备：三层不要混

外部设备完成物理输入/输出；**I/O 接口**连接主机与设备，完成地址译码、缓冲、状态报告、命令接收、速率/时序匹配。接口内可有多个**端口**（CPU 可访问的寄存器）：

| 端口 | 放什么 | 举例 |
|---|---|---|
| 数据端口 | 待收/待发的数据 | 从键盘控制器读一个字符 |
| 状态端口 | 就绪、忙、错误等状态 | 查询“数据是否已准备好” |
| 控制端口 | CPU 下发的命令/控制位 | 启动设备、允许中断 |

端口编址两种：**统一编址**将端口放入主存地址空间，可用相应访存指令访问，地址空间被占用；**独立编址**有单独 I/O 地址空间，通常需专门 I/O 指令。编址方式与“采用查询/中断/DMA”不是同一维度。

## 三、三种 I/O 方式：从时间线理解

### 3.1 程序查询（轮询）

```text
CPU 写控制端口启动设备 -> 反复读状态端口 -> 就绪 -> CPU 读/写数据端口 -> 主存
```

特点是 **CPU 负责检查就绪，也负责经寄存器搬运数据**；实现简单，但忙等或定时查询占用 CPU。定时查询未必每次都是空等，关键是检查频率足够高，缓冲未被新数据覆盖。

如果缓冲每装满一次需处理，单位时间需要查询多少次？先算最小间隔：

$$
T_{\text{填满}}=\frac{\text{缓冲容量(Byte)}}{\text{设备速率(Byte/s)}}
$$

要求最坏情况下不丢数据，查询间隔不大于缓冲填满时间（忽略额外时延、假设能及时取走数据）；再用每次查询执行的指令数求 CPU 开销。

### 3.2 程序中断

```text
CPU 继续执行原程序 -> 设备就绪并发中断请求
-> CPU 在允许响应的时机进入中断响应 -> 保存断点/必要状态
-> 执行中断服务程序，由 CPU 经接口搬运数据 -> 恢复现场 -> 返回
```

- **中断请求**不等于**立即响应**：普通可屏蔽外中断通常在当前指令结束后检查，还受开中断、屏蔽及优先级等约束。
- 硬件中断响应通常保存返回所需的断点 PC 和状态（具体实现依体系结构）；**通用寄存器通常由中断服务程序保存和恢复**。不要认为通用寄存器一定都由“中断隐指令”保存。
- **中断向量**用于定位中断服务程序入口；中断请求来自设备/控制器，中断服务程序则由 CPU 执行。
- **响应优先级**决定多个请求谁先被选中；**处理优先级**涉及服务程序执行时可否被其他中断打断。屏蔽字可影响后者，不能把屏蔽字直接当作固定的响应优先级排序表。
- CPU 在用户态或内核态执行时都可能遇到外中断；进入服务程序后通常运行于内核态。

**中断与异常的辨别**：设备完成、DMA 完成属于外部异步事件；缺页、除零、断点指令等与当前指令有关，属于异常/陷入的范畴。缺页处理后可能重启当前指令，普通 I/O 外中断通常返回后继续执行下一条应执行的指令。

### 3.3 DMA（直接存储器存取）

```text
CPU/驱动设置 DMA 参数（方向、主存起始地址、长度等）
-> 设备准备数据，DMA 控制器请求总线
-> DMA 控制器控制 设备接口 <-> 主存 的批量传送
-> 传送结束，DMA 控制器通常发中断 -> CPU 做结束处理
```

数据**不必逐字经过 CPU 通用寄存器**。但 CPU 并非完全不参与：启动前设置、结束后处理仍要 CPU；DMA 还会和 CPU 争用总线/主存。

| 方式 | 谁发现就绪 | 逐次数据由谁搬 | CPU 在等待期间 | 常见用途 |
|---|---|---|---|---|
| 程序查询 | CPU 查状态 | CPU | 忙等或定期轮询 | 简单、低速或短任务 |
| 中断驱动 | 设备通知 CPU | CPU 在服务程序中搬 | 可执行其他任务 | 零散、不可预测的输入 |
| DMA | 设备/控制器配合 | DMA 控制器控制设备接口与主存的传送 | 可执行其他任务，但可能争用总线/主存 | 高速、大块传送 |

### 3.4 DMA 怎样“借用”主存/总线

- **停止 CPU 访存**：DMA 持续占用一段时间，CPU 在这段时间不能访存；题目可能称 CPU 暂停方式。
- **周期挪用（周期窃取）**：每次准备好一个传送单位时，DMA 申请一次总线并挪用相应访存周期；**不是整个数据块期间 CPU 均不能访问主存**。题目若设定 DMA 在争用时优先，应按该条件判断。
- **交替访问**：题设规定 CPU 与 DMA 分时访问，按给定时隙计算。

注意区分 **“一个 DMA 数据块”**、**“一次总线请求/传送单位”**、**“块传送完成后的中断”**：一个块可能申请总线多次，却通常只在块结束通知 CPU 一次。缓存一致性等真实系统细节要按题目条件处理，基础题不自行加假设。

## 五、计算题统一模板

**第一步：统一单位。** 32 bit = 4 B，64 bit = 8 B；频率 $f$ 以 Hz 代入，1 个时钟周期为 $1/f$ 秒。MB 在具体真题中如未另说明通常按 $10^6$ B 处理；若题目明确 MiB 或 $2^{20}$，依题意转换。

**第二步：画出事件粒度。** 一次缓冲就绪？一次中断？一次 DMA 总线请求？一个 DMA 块？四者可能不是一回事。

**第三步：列式。** 以下只适用于每次事件恰好服务题设指定数据量、持续按给定速率工作等条件：

$$
\begin{aligned}
T_{\text{填满}}&=\frac{B_{\text{缓冲}}}{R_{\text{设备}}} \\
N_{\text{中断/秒}}&=\frac{R_{\text{设备}}}{B_{\text{每次服务}}} \\
P_{\text{CPU}}&=\frac{N_{\text{事件/秒}}\,C_{\text{每次事件}}}{f_{\text{CPU}}}\times100\% \\
N_{\text{DMA 总线请求}}&=\left\lceil\frac{B_{\text{数据块}}}{B_{\text{每次总线传送}}}\right\rceil
\end{aligned}
$$

若题目按整数个块统计一段时间的传送，不能盲目使用连续速率除法：检查是否需要向上取整、是否仅统计完整传送、最后一块是否不足。

### 例 1：2018 第 43 题的关键数字（据公开整理页简述）

题设 CPU 为 $500\,\text{MHz}$、CPI=4，接口缓冲为 32 bit；设备 A 为 $2\,\text{MB/s}$，定时查询一次至少 10 条指令；设备 B 为 $40\,\text{MB/s}$，一次中断总开销至少 400 个时钟周期；DMA 块为 $1000\,\text{B}$、前后处理合计 500 个周期。

1. A 的 4 B 缓冲每 $4/(2\times10^6)=2\,\mu\text{s}$ 填满，查询间隔**至多** $2\,\mu\text{s}$。每秒至少 $5\times10^5$ 次查询，CPU 时间占比至少 $5\times10^5\times10\times4/(500\times10^6)=4\%$。
2. B 的缓冲每 $4/(40\times10^6)=0.1\,\mu\text{s}$ 填满，而中断服务至少 $400/(500\times10^6)=0.8\,\mu\text{s}$；按单缓冲逐次服务的题设，来不及，不能用该中断方案保证不丢数据。
3. B 若用 DMA，每秒最多 $40\times10^6/1000=40000$ 块；CPU 用于启动与结束的时间占比最大为 $40000\times500/(500\times10^6)=4\%$。这是 **CPU 开销**，不等于数据真正占用总线/主存的时间比例。

“至少/至多/最大”不可省：计算的是给定速率与事件开销假设下的界限；不能无条件推广到任意工作负载。

### 例 2：2022 第 44 题的计数方法（据公开整理页简述）

每扇区 $512\,\text{B}=4096\,\text{bit}$，磁盘控制器缓冲 $64\,\text{bit}$；按题设缓冲每满一次申请一次总线，则一扇区 DMA 总线请求数：

$$
4096/64=64\text{ 次。}
$$

**不是 1 次，也不是 512 次**：一个扇区是数据块，64 bit 是每次请求搬运的单位。周期挪用意味着 DMA 占用所需周期；其余时间 CPU 可以访存。

### 例 3：自编小练习（并非真题）

设备速率 $8\,\text{KiB/s}$，每次就绪产生一个中断并传 $2\,\text{B}$；CPU 主频 $1\,\text{GHz}$，每次中断开销 1000 周期。求每秒中断数和 CPU 占比。

<details>
<summary>展开答案</summary>

$8\,\text{KiB/s}=8192\,\text{B/s}$；每秒中断 $8192/2=4096$ 次；占比 $4096\times1000/10^9=0.4096\%$。这里按 KiB=$1024$ B，不能当成 $8000$ B。

</details>

## 六、最容易错的七句话

1. **“DMA 不用 CPU。”** 错：只是不逐次经 CPU 寄存器搬数据，CPU 仍负责初始化及结束处理。
2. **“用了 DMA 就不用中断。”** 错：DMA 块结束通常发中断。
3. **“周期挪用时 CPU 在整个块传送期间都不能访存。”** 错：通常只在被挪用的周期受影响。
4. **“外设发出中断请求，CPU 立刻停下当前指令。”** 错：普通可屏蔽外中断通常在指令完成后且条件允许时响应。
5. **“中断方式数据由设备直接送主存。”** 错：普通中断方式由 CPU 执行服务程序搬；直接批量传送是 DMA 的核心特征。
6. **“一次总线请求就是一次 DMA 完成中断。”** 错：请求可按小单位多次发生，完成中断通常按块通知。
7. **“给了速率和缓冲大小就直接套 CPU 占比公式。”** 错：先确定一次事件服务多少字节、多少周期，是否有额外开销或多个缓冲。
